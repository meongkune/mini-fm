# Mini FM 문제 해결 기록

실제로 플레이하면서 발견한 치명적인 문제와 원인, 해결 방법, 검증 방법을 정리한 기록입니다.
각 항목은 **증상 → 원인 → 해결 → 검증** 순서로 적었습니다.

## UI · 화면

### 1. 경기 중 교체 화면을 스크롤하면 선수 아이콘이 머리글 위로 떠오름
- **증상**: 경기 중 `교체·위치` 시트를 열고 아래로 스크롤하면, 위로 밀려 올라간 경기장의 선수 아이콘(CB·GK 등)이 고정된 시트 머리글(`교체·위치 / 닫기`) 위에 겹쳐 보였다.
- **원인**: CSS 쌓임 순서(stacking) 문제.
  - 시트 머리글은 `position: sticky; z-index: 1`, 경기장 위 선수 버튼(`.slot`)도 `position: absolute; z-index: 1`.
  - 둘의 z-index가 같으면 DOM에서 **뒤에 나오는 요소가 위에** 그려진다. 경기장은 머리글보다 뒤에 있으므로 선수 아이콘이 머리글을 덮었다.
  - 경기장 컨테이너의 `overflow: hidden`은 잘라내기만 할 뿐 **새 쌓임 맥락(stacking context)을 만들지 않아서**, 안쪽 z-index가 바깥 요소와 직접 경쟁했다.
- **해결**:
  - 경기장 컨테이너에 `isolation: isolate`를 줘서 선수 아이콘의 z-index가 경기장 안에서만 비교되게 했다.
  - 시트 머리글의 z-index를 5로 올렸다.
- **검증**: 시트를 260px 스크롤한 상태에서 머리글과 겹치는 선수 4명의 중심 좌표로 `document.elementFromPoint`를 호출했다. 4곳 모두 머리글 요소가 반환됐다.
- **배운 점**: z-index는 같은 쌓임 맥락 안에서만 비교된다. 재사용되는 컴포넌트(경기장)는 `isolation: isolate`로 내부 z-index를 가둬 두는 것이 안전하다.

### 2. PC에서 리그 화면을 내리면 탭 줄만 따라오고 위쪽 내용이 비쳐 보임
- **증상**: PC 화면의 리그·대회 페이지를 스크롤하면 `팀 순위 / 개인 순위 / 일정 / 대항전` 탭 줄이 화면 중간에 붙어 따라오고, 그 위로 대회 헤더 일부가 비쳐 보였다.
- **원인**: 탭 줄이 모바일 기준 `position: sticky; top: calc(58px + safe-area)`로 되어 있었다. 58px은 모바일 상단바 높이다. PC 레이아웃에는 그 상단바가 스크롤 영역 안에 없어서, 탭이 위에서 58px 떨어진 곳에 멈췄고 그 틈으로 뒤 내용이 보였다.
- **해결**: PC 모드(`html.desktop`)에서는 탭 줄을 고정하지 않도록(`position: static`) 바꿨다. 모바일은 기존처럼 상단바 아래에 고정된다.
- **배운 점**: 반응형에서 sticky 오프셋을 고정값으로 두면 레이아웃마다 기준이 달라진다. 레이아웃별로 sticky를 따로 정의해야 한다.

### 3. 탭을 누르면 앱 전체가 멈춤 (SPA 이동 오류)
- **증상**: 하단 탭으로 화면을 옮기면 가끔 빈 화면이 되며 React 오류가 났다. 주소를 직접 입력해서 열 때는 재현되지 않았다.
- **원인**: `useEffect(() => window.scrollTo(0, 0), [pathname])`처럼 중괄호 없이 썼다. 최신 브라우저는 `scrollTo`가 값을 돌려주는데, 그 값이 effect의 정리 함수(cleanup)로 취급돼 다음 이동 때 React가 함수가 아닌 것을 호출하려다 터졌다.
- **해결**: `useEffect(() => { window.scrollTo(0, 0) }, [pathname])`로 중괄호를 넣어 아무것도 반환하지 않게 했다.
- **검증 방식 변경**: URL로 페이지를 여는 테스트만으로는 놓친다. 이후 모든 검증은 **실제 화면 안에서 탭을 클릭하는 E2E 방식**으로 바꿨다.

### 4. 면담 기록이 메시지함에 긴 텍스트 덩어리로 남음
- **증상**: 면담이 끝나면 대화 전문이 한 문단으로 메시지함에 붙어 읽기 어려웠다.
- **원인**: 대화를 `감독: … / 선수: …` 문자열 하나로 합쳐 메일 본문에 저장했다.
- **해결**:
  - 대화를 **구조 데이터**(`{ role, text, mood, delta }` 배열 + 결과·신뢰 변화·약속)로 저장하도록 바꿨다.
  - 메시지함에는 요약 한 줄과 `💬 대화 보기` 버튼만 보이고, 누르면 면담실과 같은 말풍선 화면이 읽기 전용으로 열린다.
  - 예전 텍스트 기록도 줄 단위로 파싱해 말풍선으로 보여준다(하위 호환).

## 게임 로직

### 5. FA 시장에서 같은 선수를 두 번 영입할 수 있음
- **증상**: 영입한 선수가 스쿼드에 두 번 나타났다.
- **원인**:
  - 영입 시 "이미 구단에 있는 선수인지"를 확인하지 않았다.
  - React 상태 갱신이 비동기라서 버튼을 빠르게 두 번 누르면 두 번 모두 통과했다.
- **해결**: 세 겹으로 막았다.
  1. 제안 전에 이미 어느 구단에든 있는 선수면 거절한다.
  2. 상태 갱신 함수 안에서 최신 로스터를 기준으로 다시 확인한다(연속 클릭 대비).
  3. 화면에 그릴 때도 ID를 중복 제거한다.

  이미 꼬인 저장 데이터는 앱을 열 때 자동으로 정리한다(로스터 중복 제거).
- **검증**: 제안 버튼을 일부러 더블 클릭해도 로스터가 1명만 늘었다.

### 6. 부상으로 10명이 되면 빈 자리를 다시 채울 수 없음
- **증상**: 경기 중 부상자가 나와 10명으로 계속하면, 그 자리(예: CB)에 교체 선수를 넣을 방법이 없었다.
- **원인**: 출전 선수 목록에서 부상자를 지우면서 자리 정보까지 함께 사라졌다.
- **해결**: 경기 상태에 **빈 자리(vacant)** 를 따로 기록해 역할(CB 등)을 보존했다. 교체 화면에서 빈 자리에 선수를 넣거나 다른 포지션 선수를 옮길 수 있게 했다.

### 7. 대항전에서 다른 리그의 같은 약칭 팀이 섞임
- **증상**: 바르셀로나와 바이에른이 같은 `FCB`로 겹쳐 결과가 꼬였다.
- **원인**: 팀 ID가 리그 안에서만 고유했다.
- **해결**: 대회 안에서는 `리그ID/팀ID` 복합 키를 쓰도록 바꿨다.

### 8. 팀 OVR이 포지션에 안 맞는 선수를 세워도 그대로임
- **증상**: 공격수를 수비 자리에 세워도 팀 OVR이 그대로라서 문제를 알아차릴 수 없었다.
- **원인**: 팀 OVR을 "가장 높은 11명 평균"으로 계산해 실제 라인업과 무관했다. (경기 엔진에는 이미 자리 적합도가 반영돼 있었다. 400경기 시뮬레이션에서 공격수·수비수 3명을 맞바꾸면 승리 117 → 46.)
- **해결**: **라인업 OVR = 자리마다 (선수 OVR × 자리 적합도)의 평균**으로 바꾸고 홈·스쿼드·전술·경기 준비 화면에 표시했다. 맞지 않는 자리에 선 선수는 `ST→LB 50%`처럼 경고한다.

## 경기 엔진 · 밸런스

### 9. 사기·전술이 결과에 거의 영향이 없고, 전력 차가 결과를 거의 결정함
- **측정**: 같은 조건으로 400~500경기씩 시뮬레이션했다.

  | 항목 | 수정 전 | 수정 후 |
  |---|---|---|
  | 동급 팀 홈 승률 | 54% | 43~47% |
  | OVR +10 팀 승률 | 86% | 72% |
  | 사기 15 vs 95 | 차이 없음 | 약 ±8% 능력치 차이 |
  | 약팀이 버스 세우기로 강팀(게겐프레싱) 상대 | 승 23% · 패 55% | 승 34% · 패 37% |

- **원인**:
  - 사기 효과가 ±3%로 너무 작았다.
  - 전술 효과(운영·압박·라인)가 선수 능력치에 더해져서, 능력치 차이를 완화하려고 만든 큰 나눗셈 계수에 같이 묻혔다.
- **해결**:
  - 사기 ±8%, 폼 ±5%로 키웠다.
  - 경기마다 "그날 컨디션"(±4%)을 넣어 이변이 나오게 했다.
  - **전술 상성을 선수 능력과 분리해 약 3배 큰 가중치**로 반영했다(역습 vs 높은 라인, 측면 공격 vs 측면 수비 부족, 압박 vs 짧은 빌드업 등).
  - 경기 전에 같은 조건으로 70~120경기를 미리 돌려 **예상 승률**을 보여준다.

### 10. 경기장 선수들이 대형 그대로 딱딱하게 움직임
- **원인**: 1분에 한 장면만 계산해서 대형 전체가 통째로 밀렸다.
- **해결**: 1분을 패스 2~3번으로 나누고 역할별로 움직이게 했다.
  - 공격 진행도에 따라 라인이 올라간다.
  - 풀백은 공 쪽 측면으로 오버래핑하고, 윙어는 안쪽으로 파고들고, 스트라이커는 뒷공간으로 침투한다.
  - 수비는 공 쪽으로 좁혀 서고, 압박과 커버를 나눠 맡는다.
  - 선수마다 고유한 위상의 흔들림을 줬다.

## 외부 API · 배포

### 11. AI 면담 응답이 최대 20초 걸림
- **측정**: 같은 요청을 반복하니 3.8초, 19.9초로 들쭉날쭉했다.
- **원인**: 기본 모델이 답하기 전에 "생각" 단계를 거쳤다. 생각을 끄는 옵션(`thinkingBudget: 0`)은 최신 모델에서 400 오류를 냈다.
- **해결**:
  - 경량 모델을 먼저 호출하고, 실패(429·503·400)하거나 12초를 넘기면 다음 모델로 넘어간다.
  - 게임은 20초 안에 응답이 없으면 규칙 기반 대화로 자동 전환해 화면이 멈추지 않게 했다.
- **결과**: 평균 **약 1.3초**.

### 12. AI 키를 안전하게 쓰기 (정적 호스팅 + 비밀값)
- **문제**: GitHub Pages는 정적 호스팅이라 브라우저 코드에 API 키를 넣으면 누구나 볼 수 있다.
- **해결**:
  - Cloudflare Worker를 **중계 서버**로 두고 Gemini 키는 Worker 비밀값(`wrangler secret put`)에만 저장했다.
  - CORS는 게임 주소만 허용한다.
  - 사용자가 키를 터미널에 직접 붙여 넣어서, 대화 기록·저장소·작업 로그 어디에도 키가 남지 않는다.
  - SportsAPI·football-data 키도 GitHub Actions Secrets에만 둔다.

### 13. 선수 능력치를 실제 데이터로 바꾸기 (하루 100회 제한)
- **문제**: 기존 능력치가 "지난 시즌 순위 + 무작위 값"이라 주전과 후보, 리그 간 수준 차이가 없었다.
- **해결**:
  - SportsAPI Pro의 팀 명단(시장가치·세부 포지션)으로 OVR을 계산하고, 선수별 능력치 레이더로 공격·수비 비중을 보정했다.
  - 무료 한도(하루 100회) 때문에 **GitHub Actions가 매일 이어서 수집**하고, 진행 상태(ID 대응표)를 커밋해서 다음 날 이어간다.
  - 약관상 원본 응답은 공개하지 않고 **계산한 결과만** 저장소에 올린다.
- **겪은 문제**:
  - 순위표 응답 형식이 문서와 달라(평평한 배열) 첫 실행에서 팀 목록이 비었다. 4회만 쓰는 시험 실행으로 먼저 확인하고 고쳤다.
  - 이적·강등 선수가 매칭되지 않아 **전체 리그 기준 매칭**과 한 단어 이름 규칙을 추가했다.

### 14. GitHub Actions가 커밋해도 사이트가 다시 배포되지 않음
- **원인**: `GITHUB_TOKEN`으로 push한 커밋은 다른 워크플로를 트리거하지 않는다.
- **해결**: 데이터 수집 워크플로 끝에서 `gh workflow run pages.yml`로 배포를 직접 실행한다. 동시에 커밋이 올라와 push가 거절되는 경우를 위해 `git pull --rebase` 후 push한다.

### 15. 앱 내장 브라우저에서 Google AI Studio 키 발급 실패
- **증상**: 로그인은 됐지만 키 목록과 키 만들기에서 `permission denied`가 났다.
- **원인**: 내장 브라우저가 Google 도메인 사이의 인증 쿠키를 막아 API 호출이 실패했다.
- **해결**: 실제 Chrome에서 브라우저 자동화(Claude in Chrome)로 발급했다. 전용 프로젝트 `mini-fm`과 키 이름 `mini-fm 게임 AI 대화`로 구분했다.

### 16. PowerShell에서 `npx`가 실행되지 않음
- **원인**: Windows 실행 정책이 `npx.ps1` 스크립트를 막았다.
- **해결**: 보안 설정을 바꾸지 않고 `npx.cmd`를 직접 호출했다.

## 게임 밸런스 (플레이 피드백)

### 17. 내 선수를 팔면 헐값에 팔림
- **증상**: 판매 목록에 올린 선수에게 몸값의 절반 수준 제안이 오고, 수락·거절밖에 할 수 없었다.
- **원인**:
  - 상대 제안이 몸값의 80~120% 중 무작위였다.
  - 계약 1년 남음(−35%)과 이적 요청(−20%) 할인이 곱해져 기준 몸값 자체가 크게 낮아졌다.
  - 역제안 수단이 없었다.
- **해결**:
  - **희망 가격**(몸값의 80~200%)을 정해 판매 목록에 올린다.
  - 상대 구단마다 **최대 금액**(선수 수준에 따라 몸값의 115~135%)이 있다. 첫 제안은 희망가보다 조금 낮게 온다.
  - **"더 달라고 하기"**: 상대 최대 금액 안이면 합의하고, 넘으면 중간 금액으로 한 번 '최종 제안'을 받으며, 그다음에는 결렬된다.
  - OVR 78 이상 선수는 두 구단이 경쟁한다.
  - 할인을 완화했다(계약 1년 −25%, 이적 요청 −15%). 강제 매각은 75~100%로 고정했다.
- **검증**: 분데스리가 선수 3명으로 시뮬레이션한 결과, 첫 제안이 몸값의 87~115%였고 역제안으로 희망가까지 올릴 수 있었다.

### 18. 꾸준히 출전시켰는데도 평점이 나쁘면 이적 요청
- **원인**: 경기 평점이 사기에 크게 반영되고(평점 1점당 사기 ±4), 사기가 25 아래로 떨어지면 **이유와 상관없이** 이적을 요청했다.
- **해결**:
  - 출전 선수의 평점 영향을 줄였다(최대 −3).
  - 이적 요청은 **사기가 바닥이면서 분명한 이유가 있을 때만** 나온다. 이유는 5경기 이상 벤치, 감독 신뢰 25 미만, 연봉이 적정의 60% 미만인 경우다. 진행 중인 약속이 있으면 요청하지 않는다.
  - **연봉 인상 요구 면담**을 추가했다. 활약(최근 평점 7.1 이상)이나 주전급인데 연봉이 적정의 75% 미만이면 시즌에 한 번 면담을 요청하고, 약속하면 5라운드 안에 재계약해야 지킨 것으로 판정된다.

### 19. 능력치 수집이 예상의 40% 속도로만 진행됨
- **증상**: 하루 95회 요청인데 레이더 보정은 하루 32~41명뿐이었다. 2주 동안 579명으로, 예상(약 1,300명)의 절반에도 못 미쳤다.
- **원인**: 레이더 데이터가 없는 선수(API가 404로 응답) 56명을 "아직 못 받음" 상태로 남겨 두었다. 우선순위(내 리그·OVR 높은 순) 맨 앞에 있던 이 56명을 **매일 처음부터 다시 요청**해서 하루 한도의 약 60%를 버렸다.
- **해결**: 응답이 없는 선수는 `rad: 'none'`으로 표시해 다시 요청하지 않는다. 기존 56명도 같은 표시로 정리했다.
- **검증**: 실행 로그에서 매번 같은 56건의 404가 반복되던 것을 확인했다(`gh run view --log`). 수정 후 남은 대상은 1,908명, 하루 약 90명 기준 약 22일이다.
- **배운 점**: 외부 API의 "데이터 없음"과 "아직 안 받음"을 같은 상태로 두면 재시도 루프가 생긴다. 한도가 있는 수집기는 실패 상태를 따로 기록해야 한다.

### 20. 경기가 전부 오픈 플레이 — 세트피스·재개가 없음
- **증상**: 코너킥 숫자는 올라가는데 코너킥에서 골이 나오지 않았고, 페널티킥·프리킥 골이 없었다. 매 분 공격이 같은 자리에서 다시 시작해 "항상 골킥으로 재개"하는 것처럼 보였다.
- **원인**: 엔진이 매 분 "점유 → 찬스 → 슈팅"만 계산했다. 코너킥은 통계용 `corners++`뿐이었고, 경기장 연출은 매 분 빌드업부터 다시 그렸다. 실제 축구는 골의 약 25~30%가 세트피스인데, 이 통로가 없어서 약팀이 이길 방법이 "확률 운"뿐이었다.
- **해결**:
  - 코너킥: 키커의 킥(기술·창의성) + 공중볼 싸움(공격 4명 vs 수비 5명 + 골키퍼 공중볼) + 루틴 상성(니어 포스트 ↔ 지역 방어, 파 포스트 ↔ 대인 방어)으로 헤더 찬스를 계산한다.
  - 반칙 위치를 나눴다: 박스 안이면 페널티킥(키커 결정력·기술 vs 골키퍼 선방, 평균 약 76%), 슈팅 거리면 직접 프리킥, 측면이면 크로스 프리킥.
  - 장면마다 재개 방식(골킥·골키퍼 캐치·스로인·프리킥)을 기록해 경기장에 보여준다.
  - 골·교체·부상·카드에 따라 전·후반 추가시간을 정한다.
  - 세트피스 골이 생긴 만큼 오픈 플레이 찬스(0.165 → 0.12)와 결정력(0.3 → 0.22)을 낮췄다.
- **검증**: 8개 리그 2,744경기 시뮬레이션. 경기당 3.15골 → 2.72골, 무승부 20.8% → 22.9%, 세트피스 골 0% → 약 26%, 퇴장 0.26 → 0.13.

### 21. 장면을 차례로 보여주자 결과가 먼저 보임 (스포일러)
- **증상**: 한 분에 장면이 여러 개(슈팅 → 선방 → 코너킥 → 헤더 골) 생기도록 바꾸자, 코너킥 장면이 시작되기도 전에 스코어보드와 자막에 골이 먼저 떴다.
- **원인**: 엔진은 1분을 한 번에 계산하고 화면은 그 결과를 나중에 재생한다. 그런데 스코어·자막은 엔진의 최신 상태를 바로 읽었다.
- **해결**: 장면(tick)마다 시작 전 값(`sc0`·`n0`·`gs0`)과 끝난 뒤 값(`sc`·`n`·`gs`)을 함께 기록한다. 화면은 지금 보여주는 장면이 슈팅까지 진행된 뒤(장면 길이의 약 72%)에야 끝난 뒤 값을 쓴다.
- **함께 고친 것**: 중계 문구를 고르는 데 경기 난수를 쓰고 있어서, 문구를 만들지 않는 빠른 계산(AI 경기·승률 예측)과 화면 경기의 결과가 달랐다. 문구는 해시로 고르게 바꿨다.
- **검증**: 같은 seed 200경기를 ① 1분씩 재생 ② 전반·후반 건너뛰기 ③ 문구 없는 빠른 계산으로 돌려 스코어·득점자·득점 시간·추가시간이 200경기 모두 같았다(수정 전에는 ②와 ③이 182경기에서 달랐다). 배속과 건너뛰기는 결과에 영향이 없다.

### 22. 능력치를 엔진에 넣자 점유율이 한쪽으로 쏠림
- **증상**: 시험 경기에서 한 팀이 점유율 81%를 기록했다. 시뮬레이션으로 보니 점유율 70%를 넘는 경기가 25%였다(실제 리그는 10% 안팎).
- **원인**: 점유 확률 = 0.5 + 중원 능력 차/`K_POSS` + 전술 상성/`K_TMID`. 세트피스·능력치 작업으로 중원 계산에 기술·전술이 들어가고 AI 구단의 점유율 전술(+4)·중앙 미드필더 숫자(+2/명)가 겹치면서, 분마다 공격권이 한쪽으로 크게 기울었다.
- **해결**: 계수를 완화했다(`K_TMID` 70 → 120, `K_POSS` 110 → 150). 전술·능력 차의 방향은 그대로 두고 크기만 줄였다.
- **검증**: 프리미어리그·분데스리가·라리가 1,066경기에서 높은 쪽 점유율 평균 63.2% → 59.5%, 70% 초과 경기 24.8% → 10.2%. 경기당 골(2.74)·무승부(23%)·강약 팀 승률은 그대로였다.

### 23. 브렌트퍼드 주전 공격수(이고르 치아구)가 명단에 없음
- **증상**: 2025-26 브렌트퍼드 명단에 주전 공격수 이고르 치아구가 없었다.
- **원인 ①**: 시즌 가져오기 도구가 1군을 **25명**으로 자르면서 기준으로 *추정 OVR*(나이·난수로 만든 값)을 썼다. 실제 시장가치 능력치는 가져온 뒤에 붙기 때문에, 자를 때는 주전과 유스를 구분하지 못했다.
- **원인 ②**: 점검 워크플로(`squad-check.yml`)로 원본을 비교해 보니, football-data.org의 브렌트퍼드 명단(30명)에는 치아구가 **아예 없었다**. API-Football 현재 명단에는 있었다.
- **해결**:
  - 1군 상한을 게임 선수단 상한과 같은 30명으로 올리고, 21세 이상 성인을 먼저 뽑는다.
  - 원본에 빠진 선수는 `tools/squad_fixes.json`에 손으로 적고, 시즌 가져오기 때마다 자동으로 다시 넣는다(`apply_squad_fixes.mjs`).
  - 이미 진행 중인 세이브에도 데이터에 새로 생긴 선수가 원래 구단에 합류하도록 했다(`effectiveTeams`).
  - 명단 파일이 새로 만들어지면 SportsAPI 시장가치 능력치를 다시 받는다.
- **참고**: 김지수는 두 API 모두 2025-26 브렌트퍼드 명단에 없었다. 그 시즌에는 임대로 팀을 떠나 있었다.

### 24. 명단 자동 보충이 다음 시즌 이적을 섞음 (되돌림)
- **증상**: API-Football 현재 명단으로 빠진 선수를 자동으로 채우자, 아스널에 콘사·메슬리에가 들어오고 마르티넬리·트로사르가 빠지는 등 엉뚱한 명단이 됐다. 함부르크는 네덜란드 유스팀 선수들로 채워졌다.
- **원인**:
  - 오늘이 2026년 11월이라 API-Football의 '현재 명단'은 **2026-27 시즌** 명단이었다. 게임 데이터는 2025-26 시즌이다.
  - 무료 플랜은 2022~2024 시즌만 조회할 수 있어 2025-26 명단을 직접 받을 수 없다.
  - 구단 이름 검색이 이름이 비슷한 다른 구단을 고른 경우도 있었다.
- **해결**: 데이터 커밋을 즉시 되돌리고(`git revert`) 자동 보충 도구를 지웠다. 확인한 선수만 손 보정 목록에 적는 방식으로 바꿨다.
- **배운 점**: "현재"라는 말이 붙은 API는 데이터의 기준 시점(시즌)을 먼저 확인해야 한다. 외부 데이터로 기존 데이터를 **빼는** 작업은 사람이 결과를 확인한 뒤에만 반영한다.


### 25. 연봉이 현실과 동떨어짐 (중소 구단 선수는 과다, 빅클럽 스타는 과소)
- **증상**: 브렌트퍼드 골키퍼 켈러허 연봉이 €6.2M(약 93억)으로, 공개 추정치(약 €3M)의 두 배였다. 반대로 케인(바이에른)은 €6M, 홀란(맨시티)은 €11.6M으로 실제의 4분의 1~절반 수준이었다.
- **원인**: 연봉을 선수 OVR 하나로만 계산했다(`0.9 × 1.11^(OVR−72) × 리그 배수`). 실제 연봉은 **어느 구단이 주느냐**에 크게 좌우되는데 구단 규모가 빠져 있었다. 시장가치로 매긴 OVR은 골키퍼가 높게 나오는 경향도 있어 켈러허가 과하게 받았다.
- **해결**: 연봉 = 능력가치(나이 할인 없는 몸값)^0.65 × 슈퍼스타 프리미엄 × 리그 규모 × **구단 규모**(주전 11명 평균 능력, 0.65~1.45배) × 나이. 진행 중인 세이브는 한 번 다시 매기고(협상으로 더 받던 비율은 유지), 구단 수입 규모도 연봉 총액 비율만큼 맞춰 FFP 비율이 갑자기 바뀌지 않게 했다.
- **검증**: 홀란 €27.7M · 라이스 €16.5M · 케인 €14.5M · 켈러허 €3.9M · 묀헨글라트바흐 주전 €1~1.5M. 개발 세이브(브렌트퍼드)는 연봉 총액 €67M → €50M, 매출 대비 연봉 83% 유지.

### 26. 실제 연봉 자료의 품질 (크라우드소싱)
- **배경**: 무료로 실제 연봉을 주는 곳은 TheSportsDB뿐이었다(football-data·SportsAPI·API-Football은 연봉 없음). 이용자들이 입력하는 자료라 값이 들쭉날쭉하다.
- **확인한 문제**: 켈러허는 £520,000/년(약 9.5억 원)으로, 리버풀 후보 시절 값이 갱신되지 않은 채였다(브렌트퍼드 주전 추정 약 €3M). 주급으로 적힌 선수도 있었다. 무료 키는 목록 조회가 10개까지라 구단 단위로 한 번에 받을 수 없었다.
- **해결**:
  - 선수마다 '검색 → 상세' 2회로 받고, 생년월일(나이 ±1)로 같은 선수인지 확인한다. 하루 50분씩 약 700명, 90일마다 다시 받는다.
  - 게임에서는 실제 값이 추정 연봉의 0.4~2.5배 안일 때만 쓴다. 주급일 수 있으니 ×52 값도 같이 비교한다.
  - 재계약한 연봉은 협상 값이라 덮어쓰지 않는다.
- **검증**: 홀란 보도 €31.9M(추정 €27.7M) → 실제 사용. 켈러허 €0.6M → 낡은 값으로 보고 추정 €3.9M 사용. 주급 €0.075M → ×52 = €3.9M로 실제 사용.


### 27. FFP 징계가 부당하게 나옴 (사채 상환·연봉 개편)
- **증상**: 2026-27 시즌 시작과 함께 "최근 3시즌 손익 -€25M (허용 -€8.8M)"로 FFP 위반 징계(벌금·영입 금지)를 받았다. 시즌 결산에 "사채 상환 €12M"이 함께 찍혀 있었다.
- **원인 ①**: 사채를 빌릴 때는 현금만 늘고 FFP 수입으로 치지 않았는데, 갚을 때는 `book()`으로 기록해 **손실로 셌다**. 빌린 돈을 갚는 것은 손익이 아니다.
- **원인 ②**: 시즌 중간에 연봉 체계를 개편하면서 구단 수입 규모(=FFP 허용 적자 기준)를 줄였다. 지난 시즌 지출 대부분은 예전(높은) 연봉으로 쌓였는데, 줄어든 기준으로 심사됐다.
- **해결**: 사채 대출·상환은 현금만 움직이는 `cashOnly()`로 바꿔 FFP 손익에서 뺐다. 연봉 개편 알림과 FFP 징계가 둘 다 있는 세이브는 한 번 징계를 취소하고 벌금을 돌려준다(`ffpAppeal`).
- **함께 고친 것**: 개발 모드(React StrictMode)에서 effect가 두 번 실행되면 벌금이 두 번 환급됐다. 조건 검사를 `setSave` 업데이트 함수 안으로 옮겨 최신 상태로 다시 확인하게 했다(연봉 이전도 같은 방식).
- **검증**: 개발 세이브에 같은 상황을 만들어 징계 해제·벌금 €5.9M 1회 환급(€10.6M → €16.5M)·알림 1건을 확인했다.

### 28. '살 수 있는 선수만'을 누르면 아무도 안 나옴
- **증상**: 팀별로 보면 우리 현금으로 충분히 살 수 있는 선수가 있는데, 필터를 켜면 목록이 비었다.
- **원인**: 필터 조건이 "이적료 ≤ 현금 **그리고** 연봉 ≤ 임금 예산 여유"였다. 연봉 총액이 임금 예산을 꽉 채운 상태(여유 €0)라 연봉 조건 때문에 모든 선수가 빠졌다. 화면에는 이유가 나오지 않았다.
- **해결**: 필터를 "이적료를 낼 수 있는 선수"로 바꾸고, 카드마다 `✔ 영입 가능` / `연봉 예산 초과`를 따로 표시한다. 임금 예산 여유가 없으면 목록 위에 이유와 해결 방법(임금 예산 올리기·연봉 높은 선수 팔기)을 띄운다.

### 29. 경기 결과를 다시 뽑는 꼼수 · 저장 버튼
- **증상**: 경기 결과는 '결과 저장' 버튼을 눌러야 저장됐다. 지는 경기에서 다른 화면으로 나갔다 들어오거나 새로 고침하면 경기가 처음부터 새로 만들어져(새 난수) 결과를 다시 뽑을 수 있었다.
- **해결**:
  - 경기 seed를 시즌·라운드·대진으로 고정했다. 다시 들어와도 같은 조건이면 같은 경기다.
  - 종료 휘슬이 울리면 버튼 없이 자동 저장한다. 결과 화면은 끝난 경기 기준으로 고정해 보여 주고 '다음 경기'로 넘어간다.
  - 경기 중 다른 화면으로 나가면 남은 시간을 AI가 지휘해 끝까지 진행하고 저장한다.
  - 경기 시작을 세이브에 표시(`liveMatch`)해서, 새로 고침·창 닫기로 빠져나가도 다음에 열면 끝까지 진행해 저장한다. 창을 닫으려 하면 브라우저 경고도 띄운다.
  - 같은 경기 키로 두 번 저장되지 않게 막았다(`lastMatchKey`).
- **함께 고친 것**: 저장하면 라운드가 넘어가면서 경기 키(라운드 포함)가 바뀌어 결과 화면 대신 다음 경기 준비 화면이 떴다. 끝난 경기의 키를 고정해 해결했다.
- **검증**: 개발 서버에서 ① 끝까지 진행 → 자동 저장·결과 화면 유지 ② 1분에 다른 화면으로 이동 → 아스널 2:1 브렌트퍼드로 저장 ③ 경기 중 새로 고침 → 다음 방문 때 자동 진행·저장 안내까지 확인했다.

### 30. 면담 요청이 시즌이 바뀌어도 계속 남음
- **해결**: 면담 요청은 다음 경기 전까지 '지금 면담하기' 또는 '넘기기'를 고른다. 답하지 않고 경기를 치르면 '답하지 않음'(사기 −4)으로 기록이 남고, 기록에서 '지금이라도 면담'을 할 수 있다.

### 31. 선수 사진 통일 파이프라인 (얼굴 기준 자르기·배경 제거)
- **목표**: 중계 그래픽처럼 모든 선수를 같은 틀(구단 색 원 안에 머리~가슴)로 보여 준다. 공식 프로필 사진은 저작권이 있어 쓰지 않고, 자유 라이선스인 위키미디어 사진을 가공한다.
- **방법**: OpenCV로 가장 큰 얼굴을 찾아 얼굴 폭의 2.9배 정사각형(얼굴 위 여백 0.7배)으로 자른다. rembg(isnet)로 배경을 지운 뒤 160px WebP로 저장한다. 얼굴이 없거나 작거나 가장자리에 걸리면 실루엣으로 대신한다.
- **겪은 문제**:
  - rembg가 다른 opencv 패키지를 끌어와 `cv2.CascadeClassifier`가 사라졌다. 설치 뒤 opencv를 버전 고정(`--force-reinstall --no-deps`)으로 다시 깔아 해결했다.
  - `python … | tee`가 파이썬 실패를 숨겨 커밋 단계에서야 실패했다. `set -o pipefail`을 붙였다.
  - 위키미디어 썸네일은 표준 크기만 허용된다(800px → 400 오류). 960px로 바꿨다.
- **결과(시험)**: 브렌트퍼드·묀헨글라트바흐 52명 중 36명 성공(얼굴 없음 6 · 가장자리 5 · 배경 제거 실패 5), 46장 330KB.

### 32. 쌓아 둔 레이더 능력치가 하룻밤에 사라짐
- **증상**: 11-09까지 941명이던 레이더(세부 능력치)가 11-10 수집 뒤 161명으로 줄었다(프리미어리그 282 → 23, 분데스리가 223 → 9).
- **원인**: 명단을 새로 가져오면 팀 명단을 다시 받도록 바꿨는데(#23), 그 단계가 선수 능력치 항목을 **새 객체로 덮어써서** 이미 받아 둔 `rad`·`gk`가 지워졌다. 상태 파일의 '레이더 받음' 표시도 같이 사라져 같은 선수를 다시 요청하려 했다.
- **해결**: 덮어쓸 때 기존 레이더를 유지하고, 시장가치가 바뀐 만큼만 같이 옮긴다. 11-09 커밋에서 레이더 780명과 상태 표시를 되살렸다.
- **검증**: 복구 후 941명(11-10 실행에서 새로 받은 선수 포함).
- **배운 점**: 외부 데이터를 다시 받는 단계는 "있는 값에 덧붙이기"로 만들어야 한다. 커밋별 개수를 비교하는 습관이 있었으면 바로 잡았을 문제다.

### 33. 연봉이 실제보다 너무 쌈 (구단 총액 36~76%)
- **증상**: 이적료는 실제 시장과 비슷한데 연봉은 너무 쌌다. 구단별 연봉 총액이 공개 추정치의 36~76%였다(바이에른 36%, 묀헨글라트바흐 39%).
- **원인**: 연봉을 선수마다 "능력 × 리그 × 구단 규모" 공식으로 따로 만들었다. 주전 몇 명을 빼면 나머지가 너무 싸게 나왔고, 구단 규모를 주전 능력으로만 추정해 분데스리가 구단들이 특히 낮았다.
- **해결**: 실제 구단처럼 **구단 연봉 총액을 먼저 정하고 선수 가치 비율로 나눈다**.
  - 프리미어리그·분데스리가는 구단별 총액을 공개 추정치(대략값)로 둔다. 스쿼드 가치만으로는 구단이 돈을 쓰는 규모를 알 수 없기 때문이다(브렌트퍼드는 선수 가치는 높지만 연봉은 적게 쓴다).
  - 나머지 리그는 "리그 최상위 총액 × 0.8^(1위와의 전력 차)"로 계산한다.
  - 선수 몫은 능력가치^0.55 × 나이(신인 계약은 적게)로 정하고, 골키퍼는 0.7배를 준다.
  - 영입 때 요구 연봉은 "우리 구단 기준"과 "지금 구단에서 받는 연봉" 중 큰 쪽에 15%를 더한다.
- **결과**: 홀란 €33.5M · 케인 €32.2M · 라이스 €17.7M · 켈러허 €4.2M · 묀헨글라트바흐 주전 €4~5M. 진행 중인 세이브는 협상 웃돈·실제 보도 연봉·재계약 연봉을 유지한 채 한 번 다시 매기고, 수입 규모도 같은 비율로 맞춰 FFP 비율은 그대로 둔다.

### 34. 개막 전인데 AI 선수가 "계속 벤치에만 앉아 있다"며 불만
- **증상**: 새로 팀을 맡고 첫 경기 전에 벤치 선수(미토마)를 면담하자 "최근에 계속 벤치에만 앉아 있는 걸 보면…"이라며 서운해했고, "아직 한 경기도 안 했다"고 바로잡자 신뢰가 더 떨어졌다(−7).
- **원인 ①**: AI에게 주는 선수 상황이 선발 명단에 없는 선수를 항상 "최근 선발에서 빠져 있음"으로 적었다. 시즌 진행·출전 기록이 빠져 있어서 AI가 벤치 기간을 지어냈다.
- **원인 ②**: AI 규칙이 "구체적인 답이 없으면 신뢰 0 이하"라서 안부 질문이나 사실 정정에도 신뢰를 깎았다.
- **해결**:
  - 상황 정보에 사실만 넣는다: 시즌 몇 경기째인지(개막 전이면 '공식 경기 없음'), 이 선수 출전 수, 다음 경기 선발 여부, 실제 연속 결장 수.
  - AI 규칙 추가: 상황에 없는 사실을 지어내지 말 것, 안부·일상 질문은 신뢰 0~+2, 감독의 사실 정정은 인정하고 깎지 말 것, 불만 근거가 없는 일반 면담은 협조적으로.
- **검증**: 같은 상황(개막 전·벤치·자존심 높은 선수)으로 서버에 직접 3턴 대화 → "몸 상태 문제없고 개막을 앞두고 열심히 준비하고 있다" 등 담담한 답, 신뢰 +1·+1·+1.

### 35. 시장가치가 붙은 선수가 62%뿐 (이름 맞추기 실패)
- **원인**: SportsAPI 구단 명단의 선수를 우리 선수와 이름으로 맞출 때 ① 하이픈·띄어쓰기 차이("Hee-chan" ≠ "Heechan")를 못 넘었고 ② 9개 리그 전체에서 찾다 보니 'Silva'·'Martínez' 같은 흔한 이름은 후보가 여럿이라 버렸다 ③ 'I. Thiago'·'Danilo' 같은 짧은 이름을 못 맞췄다.
- **해결**: 띄어쓰기·하이픈을 무시한 비교를 추가했다. 1차로 맞춘 선수가 가장 많이 속한 우리 구단을 그 SportsAPI 구단으로 보고, 못 맞춘 선수는 **그 구단 안에서만** 성·이름 단어·짧은 이름으로 다시 찾는다(나이 차 1 이하, 후보 하나일 때만). 구단 명단을 다시 받아(약 176회, 레이더 수집 이틀 멈춤) 적용한다.

### 36. CI 검사를 넣자마자 찾은 데이터 오류
- K리그 파일에 같은 선수(신일연)가 충남아산과 수원 FC 두 구단에 등록돼 있었다. API-Football 현재 명단이 이적 중인 선수를 두 구단에 모두 내보낸 것. 가져오기 도구가 처음 나온 구단에만 넣도록 고쳤다.


### 37. 코너킥 크로스가 아무도 없는 곳으로 날아감
- **원인**: 수비가 걷어낸 코너킥 장면에서 "크로스가 수비 머리에 닿음" 단계를 건너뛰고 곧바로 "박스 밖으로 걷어냄" 위치로 공을 옮겼다. 그래서 크로스가 빈 곳으로 가는 것처럼 보였다.
- **해결**: 걷어낸 코너킥은 준비 → 크로스가 수비 머리에 닿음 → 걷어냄 3단계로 보여준다.

### 38. 같은 선수에게 온 두 번째 이적 제안이 판매 뒤에도 남음
- **증상**: 한 선수에게 두 구단이 제안했을 때, 한 곳에 판 뒤에도 다른 제안의 수락 버튼이 남아 있었다. 눌러도 돈은 들어오지 않았지만(선수 소속 확인) 헷갈렸다.
- **해결**: 판매가 확정되면 같은 선수에게 온 나머지 제안을 "다른 구단으로 이적해 취소" 처리한다.

### 39. 이적 협상이 너무 경직됨
- **판매**: '더 달라고 하기'만 있어서 희망가로만 요구할 수 있었다 → 원하는 금액을 직접 적어 요구할 수 있게 했다. 상대 최대 금액 안이면 합의, 조금 넘으면 최대 2번까지 중간 금액으로 다시 제안, 1.6배를 넘게 부르면 협상이 깨진다.
- **영입**: 상대는 늘 가치의 110%(핵심 140%)를 원해서 가치만큼 제시하면 거의 안 됐다 → 선수 역할에 따라 핵심 130%·주전 105%·후보 90%(30세 이상은 10% 덜)로 바꾸고, 협상할 때마다 4%씩 양보한다(가치의 85%까지). 역제안 금액도 원하는 금액과 제시액 사이로 낸다.

### 40. AI 연봉 협상 (재계약·신규 영입 개인 조건)
- **요청**: 연봉도 버튼 한 번이 아니라 대화로 협상하고, "지금은 이만큼밖에 못 주지만 한 시즌 잘하면 올려 준다" 같은 약속도 걸 수 있게.
- **설계**:
  - 면담실에 조건 패널(연봉·기간·'활약 시 다음 시즌 25% 인상' 약속)을 붙였다. 조건을 내밀면 Gemini가 성격·신뢰·감독 말을 보고 수락/역제안/결렬과 역제안 금액·기간을 답한다.
  - **말로 후려치기 방지**: 게임이 선수별 최저 수락 연봉(원하는 연봉의 80~100%: 인상 약속+신뢰 50 이상 −7%, 충성심 높으면 −5%, 자존심 높으면 +5%)을 따로 계산한다. AI가 '수락'해도 그 밑이면 역제안으로 바꾼다. 역제안 금액도 이 범위 안으로 자른다.
  - 인상 약속은 시즌이 끝날 때 판정한다(평균 평점 6.9·10경기 이상). 조건을 채우면 다음 시즌 5라운드 안에 약속한 연봉 이상으로 재계약해야 지킨 것이 되고, 못 채우면 약속이 사라진다(선수도 받아들임).
  - 시즌이 바뀌어도 신뢰·지킨/어긴 약속·면담 기록이 이어지도록 고쳤다(예전에는 시즌마다 초기화됐다).
  - 들어가는 곳: 선수 상세 → 계약 → '대화로 연봉 협상', 메시지함의 재계약·연봉 인상 요청, 영입 때 이적료 합의 뒤 '선수와 연봉 협상 후 계약'.
- **검증(서버 직접 호출)**: 희망 €5.5M인 선수에게 €4.2M 제안 → €5M 역제안. 구체적이지 않은 "나중에 올려 주겠다" → 의심. €5M + 인상 약속 → 계약 합의(신뢰 +5).

### 41. 선수+현금 이적 · 임대 · AI 단장 협상
- **요청**: 이적료만이 아니라 우리 선수를 얹는 거래, 임대(영입·보내기), 상대 구단과도 AI로 협상.
- **선수+현금**: 영입 화면에서 우리 선수를 하나 끼워 넣으면, 상대 구단이 그 선수를 따로 평가한다. 그 포지션이 모자라면 가치의 90%, 적당하면 75%, 넘치면 60%로 쳐준다. 상대 주전급이면 +10%p, 한참 못 미치면 절반, 31세 이상은 15% 덜 쳐준다. 이 금액만큼 현금을 덜 낸다. 역제안도 '현금 얼마 + 그 선수'로 나온다. 확정하면 그 선수는 상대 구단으로 가고, 그 선수 연봉은 임금 예산 계산에서 빠진다.
- **임대 영입**: 시즌 끝까지 빌린다. 임대료 + 연봉 부담 비율(100/75/50%)을 고른다. 핵심(상위 3명)·주전(상위 11명, 24세 이상)은 빌려주지 않는다. 연봉을 적게 낼수록 임대료를 더 요구한다. 임대 온 선수는 재계약·판매·방출·재임대를 막았다.
- **임대 보내기**: 선수 상세 → '임대 보내기'. 같은 세부 포지션(RB·CB·ST…)에서 그 선수보다 나은 선수가 적은 구단만 후보로 보여 준다(주전 예상·로테이션). 조건이 같으면 작은 구단부터 보여 준다. 상대가 연봉을 전부 내고 우리는 임대료를 받는다. 어린·후보 선수는 사기가 오르고, 주전급 베테랑은 사기가 떨어진다.
  - 처음에는 포지션(DF 4자리)으로만 비교해서 리버풀이 21세 풀백의 '주전 예상' 구단으로 나왔다. 세부 포지션 기준으로 바꿨다.
- **시즌 말 복귀**: 다음 시즌으로 넘어갈 때, 계약 만료 처리보다 먼저 임대 선수를 원래 팀으로 돌려보낸다. 빌려 온 선수의 계약은 '이번 시즌까지'라서, 순서가 바뀌면 FA로 풀려 버린다.
- **AI 단장 협상**: 수락·역제안·거절과 금액은 게임 규칙이 정한다. Gemini(단장)는 그 결정을 자기 말로 전하기만 한다. 감독의 근거(후보 선수·계약 1년 남음·선수가 떠나길 원함·필요한 포지션 선수를 끼워 줌)가 설득력 있으면 양보(0~5%)를 준다. 양보는 다음 제안부터 원하는 금액에서 빠지고, 합쳐서 최대 8%, 가치의 80% 밑으로는 안 내려간다. 무례하면 단장이 협상을 접는다. 서버가 안 되면 게임 판단 문구가 그대로 나온다.
- **검증(브라우저 클릭)**:
  - 첼시 19세 후보 임대 → 수락, 저장 확인.
  - 첼시 로테이션 선수에게 현금 €12M + 얀엘트 → 거절, 단장도 거절로 전달. 현금 €30M + 얀엘트 → '현금 €31M + 얀엘트' 역제안, 단장이 같은 금액으로 전달.
  - 바디아실에게 현금 €5M + 얀엘트 → 수락·확정: 얀엘트는 첼시로, 현금은 €5M만 나감.
  - 카요데 → 번리 임대: 명단 이동, 임대료 입금, 사기 상승.
  - 시즌 끝으로 돌려 다음 시즌 시작: 두 선수 모두 원래 팀으로 복귀, 방출 목록에 섞이지 않음. 테스트 뒤 저장은 원래대로 되돌렸다.

### 42. 돈 구조 다시 짜기 (재정 5판): 임금 예산 막대가 '공짜 버튼'이던 문제
- **증상**: 구단 운영의 '임금 예산' 막대를 오른쪽으로 밀면 손해 없이 한도만 늘었다. 반대로 실수로 왼쪽(40%)에 두면 영입·재계약이 전부 막혔다. 매출도 '시작 연봉 × 1.15'로 거꾸로 정해져 있었고, 이적료는 산 시즌에 전액 비용으로 잡혀 큰 영입 한 번에 FFP 위반이 났다.
- **해결** (`game/finance.js`):
  - 매출은 게임을 시작할 때 구단 규모로 한 번 정하고(연봉이 매출의 62%가 되게), 그 뒤로는 연봉을 따라 움직이지 않는다. 시즌 목표를 이루면 +4%, 못 이루면 −2%.
  - 운영비(매출의 31%)가 리그 라운드마다 나간다. 아무것도 안 하는 중위권 구단은 대체로 본전이다.
  - 이사회가 시즌마다 **이적 자금**과 **임금 예산**(매출의 70%)을 준다. 구단 운영의 막대는 둘을 **맞바꾸는** 것으로 바뀌었다: 임금 예산 €1M/년 ↔ 이적 자금 €2M. 공짜로 늘어나는 돈은 없다.
  - 영입·임대·FA 계약금은 통장 현금이 아니라 이적 자금에서 나간다. 선수를 팔면 받은 돈의 80%가 이적 자금으로 돌아온다.
  - 이적료는 현금으로는 바로 나가지만 FFP 손익에는 계약 기간으로 나눠 잡힌다(5년 계약 €50M → 해마다 €10M).
  - 진행 중인 세이브는 자동으로 옮긴다(`toFinanceV5`): 매출을 새 기준으로 다시 잡고, 지금 현금의 70%를 이적 자금으로, 지금 연봉 총액 +6% 이상을 임금 예산으로 준다.
- **검증**: 개발 세이브가 자동으로 옮겨졌다(이적 자금 €7M · 임금 예산 €93M · 연봉 €85M). 막대를 양 끝으로 움직여 금액이 맞바뀌는 것, 경기 뒤 정산에 운영비가 찍히는 것을 화면에서 확인했다.

### 43. AI 구단끼리의 이적 시장 (`game/market.js`)
- 이적 시장이 열린 라운드마다 다른 구단도 서로 선수를 사고판다. 구단마다 가장 약한 포지션을 찾고, 그 자리 주전보다 나은 선수를 예산 안에서 산다. 파는 쪽은 내가 영입할 때와 같은 기준으로 값을 부른다.
- 선수는 같은 수준이거나 더 강한 구단으로 간다(후보 선수만 아래로 내려간다). 다른 리그에서 사 오기도 하고 팔려 나가기도 한다. 작은 리그의 스타는 더 강한 해외 구단이 데려간다.
- 가끔 더 큰 구단이 판매 목록에 없는 내 주전에게 먼저 제안을 넣는다.
- 결과는 메시지함 '이적 시장 소식'과 이적 시장 화면 아래 '다른 구단 이적 소식'에 나온다.
- 모든 선택은 시즌·라운드·구단 ID의 해시로 정해져서 같은 세이브에서는 항상 같은 결과가 나온다.

### 44. 여러 시즌을 돌리면 리그가 무너지던 문제들 (`tools/sim_seasons.mjs`로 발견)
리그 하나를 사람 없이 6~8시즌 돌리는 도구를 만들어 돌려 보니 아래 문제가 나왔다.
- **은퇴·방출 선수가 되살아남**: 명단에서 빠진 선수가 원본 데이터에 남아 있어서 다음 시즌에 원래 구단으로 다시 붙었다(명단이 33명까지 불어남). → 리그를 떠난 선수를 `save.left`에 기록하고 명단 합성에서 뺀다.
- **리그가 늙음**: 평균 나이가 24.5 → 28.3세. AI 구단이 노장을 정리하지 않았다. → 시즌이 끝날 때 31세 이상인데 팀 내 16위 밖인 선수와 26명을 넘는 인원을 내보내고 유스로 채운다. 쓸 만한 선수는 FA 시장에 나온다.
- **전력이 해마다 부풂**: 유스 수준을 '지금 팀 전력'에 맞춰서, 팀이 강해지면 유스도 강해지는 되먹임이 있었다. → 유스 수준을 구단의 원래 규모에 맞추고, 잠재력은 '대부분 평범, 소수만 대형'으로 바꿨다. 기존 선수의 잠재력 분포도 같은 방식으로 조정했다. 소속 팀 수준을 크게 넘어선 선수는 성장이 더뎌진다.
- **부자 구단만 강해짐**: AI 구단 예산이 구단 규모에만 비례했다. → 기본 몫을 더하고 비례분을 줄였다.
- **결과(6시즌)**: 프리미어리그 평균 전력 +0.6, 상위 3팀 +0.5, 평균 나이 +0.3세, 명단 25.5명. 분데스리가·에레디비시도 범위 안.
- CI(`pages.yml`)에 `sim_seasons.mjs --check`(프리미어리그 5시즌)를 넣어, 범위를 벗어나면 배포가 멈춘다.

### 45. 경기 엔진 정교화 (`tools/diag_engine.mjs`로 실제 통계와 비교)
한 리그 전 경기를 돌려 실제 축구 통계와 나란히 보는 진단 도구를 만들고, 어긋난 곳만 고쳤다.
- **수준 낮은 리그는 골이 안 남**(에레디비시 2.2골, K리그 2.0골): AI 전술 성향을 능력치 절대값으로 정해서(82 이상 공격적, 76 미만 수비적) 낮은 리그는 거의 모든 팀이 수비적으로 나왔다. → 두 팀의 평균 수준이 기준보다 낮으면 양 팀을 똑같이 올려서 본다(두 팀의 차이는 그대로). 지금은 모든 리그가 2.8~3.0골.
- **강팀이 덜 이기고 대승이 많음**: 팀 전체에 걸리는 '그날 컨디션' 폭(표준편차 3.5%)이 팀 간 전력 차만큼 컸다. → 2%로 줄였다. 전력이 5 이상 앞선 홈팀 승률 56% → 72%.
- **유효슛이 많음**(경기당 12.6 → 10.3, 실제 약 9): 골문 안으로 가는 비율을 낮추고 그만큼 유효슛의 득점 확률을 올렸다(득점 수는 그대로).
- **오프사이드** 5.9 → 3.9, **경고** 3.5 → 4.3, **코너킥** 12.1 → 11.9.
- **득점 시간대**: 경기가 진행될수록 찬스가 늘게 해서 76분 이후 골 18.6% → 21%.
- **득점 포지션**: 수비수 득점 17.7% → 14%, 미드필더 30% → 35%.
- **경기 상황**: 2골 넘게 앞서면 힘을 빼고, 3골 넘게 지면 무리하게 올라가지 않는다.
- 배속·건너뛰기 결과 일치 검사와 엔진 검사는 그대로 통과한다.

### 46. 경기 결과 분포: 대승이 많고 무승부·홈 승률이 낮음 → 점수 차에 따른 '경기 흐름'
- **증상**(`tools/diag_engine.mjs`): 3골 차 이상 19~24%(실제 12~15%), 프리미어리그 무승부 17~19%(실제 22~25%), 분데스리가 홈 승률 36~37%, 경기당 슛 약 30개(실제 25~27), 프리미어리그 득점왕 21~23골(실제 25~30). 45번에서 그날 컨디션 폭을 줄이고 ease·chase를 넣었지만 대승은 거의 줄지 않았다.
- **원인**
  - **분 단위 확률이 점수와 사실상 무관**했다. 예전 경기 상황 보정(ease·hold·chase)은 전술 점수(tAtt·tDef)에 ±2~8을 더하는 방식인데 그 계수(K_TCHANCE 200)로는 찬스 확률이 1~4%p밖에 안 움직였다. 두 팀 득점이 서로 독립이라 한번 벌어진 경기가 그대로 더 벌어졌다. 똑같은 팀끼리 붙여도 3골 차가 15~17%(독립 포아송 기준 11%)였다. 게다가 hold·ease는 **앞선 팀의 수비를 올려** 동점골을 더 어렵게 만들어 무승부를 오히려 줄였다.
  - **분데스리가만 홈 승률이 낮다는 것은 대부분 표본 운**이었다. 진단은 리그당 306경기 한 번이라 ±5%p쯤 흔들린다. seed를 바꿔 3번 돌리면 분데스 40.8%·프리미어 43.1%로 차이가 2%p뿐이다. 진짜 문제는 **모든 리그에서 홈 이점이 조금 약한 것**이었다 — 홈 이점이 점유(중원 +5)에만 걸려 있었다.
  - **슛**: 찬스 없이 끝난 공격의 16%가 중거리 슈팅이라 경기당 13개쯤 나왔다. **득점왕**: 슈터를 고르는 가중치(공격력²)가 완만해 팀 내 골이 고르게 퍼졌다.
- **해결** (`frontend/src/engine/match.js`)
  - `flowOf` 신설: 점수 차에 따라 그 팀이 만드는 **찬스 수에 직접 배수**를 건다. 앞선 팀은 템포를 늦춰 찬스가 줄고(1골 −14%, 2골 −36%, 3골 이상 −55%, 75분까지 −16%p 더), 뒤진 팀은 몰아붙여 찬스가 는다(1골 +8%, 2골 +14%, 시간이 갈수록 +14%p). 대신 올라온 뒤 공간으로 나가는 앞선 팀의 역습은 질이 좋다(+0.025). 예전 ease·hold·chase는 지웠다. 계수는 `FLOW`에 모아 두었다.
  - 홈 팀 찬스 ×1.18 (`HOME.ch`), 전체 득점 보정 `FLOW.base` 0.975 → 평균 골 수는 그대로.
  - 중거리 슈팅 비율 0.158 → 0.115, 그만큼 질 0.09 → 0.122 (중거리 골 비율은 8% 안팎 유지).
  - 슈터 가중치: 공격력² → 공격력^3.5, 중앙 공격수(ST) ×1.4, 포지션 가중치 FW 3.0/MF 1.3/DF 0.35 → 2.45/1.45/0.5 (`SHOT_W`) — 득점 포지션 비율을 유지하면서 스타 공격수에게 몰리게.
- **검증** (seed를 바꿔 3~4번씩 돌린 평균, 고치기 전 → 후)
  - 프리미어리그: 3골 차 17.5% → 13.3%, 무 21.5% → 24.4%, 홈승 43.1% → 43.8%, 슛 30.7 → 27.0, 득점왕 22.3 → 24.0골, 골 2.93 → 2.93, FW/MF/DF 50/38/12 → 50/37/13
  - 분데스리가: 3골 차 21.2% → 13.3%, 무 22.5% → 27.0%, 홈승 40.8% → 41.9%, 슛 29.4 → 25.6, 골 2.85 → 2.79
  - 10개 리그 모두 골/경기 2.63~2.94, 3골 차 11.7~18.3%(한 번 실행 기준), 홈승 42~47%.
  - `check_engine.mjs` 통과(배속·건너뛰기 불일치 0), `sim_seasons.mjs premier-league BRE 5 --check` 통과, 브라우저에서 한 경기를 8배속·건너뛰기로 끝까지 진행해 확인.
- **남은 것 / 주의**: 득점왕은 시즌마다 편차가 커서(같은 선수가 17~34골) 리그 1·K리그는 30골을 넘는 시즌이 잦다. 라리가·리그 1 등은 원래 데이터상 공격수 득점 비율이 57~61%로 프리미어리그보다 높다(고치기 전에도 57~59%). 진단 숫자를 비교할 때는 **한 번 실행 결과로 판단하지 말 것** — 무승부·홈 승률은 ±5%p 흔들린다.

### 46. 판매 불가 선언 · 팬 민심 · 구단주 결정 개편
- **판매 불가**: 메시지함의 이적 제안에 '🔒 판매 불가'를 넣었다.
  - 누르면 그 선수에게 온 다른 제안도 모두 거절되고, 이번 시즌에는 제안(이적 요청 선수 제안, 큰 구단의 선제안 포함)이 오지 않는다.
  - 남고 싶은 선수는 사기 +5·신뢰 +4. 이적을 원하던 선수는 사기 −10·신뢰 −8.
  - 선수 상세에서 해제할 수 있고, 판매 목록에 올리면 풀린다. 같은 시즌에 판매 목록에 올리면 선수가 배신감을 느낀다(사기 −8, 신뢰 −10, 핵심 선수면 민심 −3).
- **팬 민심이 아무 데도 영향을 안 주던 문제**:
  - 예전에는 관중 수·상품 수입에만 쓰였고, 평균으로 돌아오는 힘이 없어 바닥이나 꼭대기에 갇혔다.
  - 이제 경기 결과는 '기대 대비'로 움직인다. 강한 상대를 이기면 최대 +4, 약한 상대에게 지면 최대 −4. 아무 일이 없으면 55 쪽으로 돌아온다(경기마다 차이의 3%).
  - 민심 효과: 스폰서 수입 0.85~1.15배, 홈경기 응원 ±1.2% 경기력, 20 미만이면 팬 시위(이사회 신뢰 경기마다 −2), 85 이상이면 이사회 신뢰 +1.
  - 민심은 소수 첫째 자리까지 저장하고 화면에는 정수로 보여 준다(작은 변화가 반올림으로 사라지지 않게).
- **구단주 결정의 구멍**:
  - 사채: 재정 5판 뒤로 현금만 늘고 이적 자금은 안 늘어 쓸모가 없었다. → '구단주 대출': 매출의 20%가 이적 자금으로 들어온다. 2시즌 동안 리그 경기마다 원금+이자(총 25%)를 나눠 갚고, 이자는 FFP 손익에 비용으로 잡힌다. 동시에 2건까지.
  - 무료 입장: 그냥 돈을 내고 민심을 사는 교환이었다. → 다음 홈경기 입장 수입이 실제로 0이 되고, 관중석이 꽉 차고(홈 응원 최대), 민심 +8.
  - 승리 보너스: '5경기'라고 써 있었지만 효과가 한 번뿐이었다. → '승리 수당': 5경기 동안 이긴 경기에만 돈이 나가고, 그때마다 출전 선수 사기 +3.
  - 주급 삭감: 시즌이 바뀌어도 영원히 유지됐다. → 이번 시즌 끝까지만.
  - 명명권: 시즌마다 다시 팔 수 있었다(돈 복사). → 구단 역사상 한 번, 5시즌 계약으로 해마다 매출의 6%. 구장 이름도 실제로 바뀐다.
  - 도발: 상대와 상관없이 ±12였다. → 강한 상대를 이기면 최대 +16, 약한 상대에게 지면 최대 −16.
  - 대부분의 결정이 현금에서만 빠지고 장부(항목별 그래프·FFP)에 안 잡혔다. → 모두 book()으로 기록. 장부 반올림도 0.1 → 0.01 단위로 바꿔, 경기마다 나눠 갚는 작은 금액이 사라지지 않게 했다.
- 구단 화면에 '지금 걸려 있는 효과'(대출 잔액, 명명권, 무료 입장 예약, 승리 수당 남은 경기 등)와 민심 효과(스폰서 배수, 홈 응원)를 보여 준다.
- **검증**:
  - 계산 테스트: 약팀에게 12연패 → 민심 17.5에서 시위 발생. 그 뒤 12무 → 29로 회복. 대출 76경기 뒤 완납, 이자 누계 €6.77M(이론 €6.62M, 경기마다 반올림 차이). 무료 입장 경기는 관중 수입 0·관중 100%·민심 +8. 승리 수당은 이긴 3경기만 지급.
  - 브라우저: 결정 네 가지를 눌러 효과 목록·이적 자금 증가를 확인하고, 한 경기를 돌려 명명권 수입·대출 이자·승리 수당 차감을 정산에서 확인했다. 테스트한 저장은 원래대로 되돌렸다.

### 47. 경기 중 다른 탭에 갔다 오면 경기가 끝나 버리던 문제 외
- **증상**: 0:2로 지던 후반에 다른 탭을 눌렀다 돌아오니 패배가 기록돼 있었다.
- **원인**: 결과를 다시 뽑는 꼼수를 막으려고, 경기 화면을 떠나는 순간 남은 시간을 AI가 대신 끝까지 진행해 저장하게 해 두었다. 같은 경기는 같은 seed라서 다시 들어와도 결과를 바꿀 수 없으니, 이 처리는 필요 이상으로 강했다.
- **해결** (`pages/Match.jsx`):
  - 앱 안에서 다른 탭으로 가면 경기를 화면 밖(모듈 변수)에 멈춘 채 보관한다. 돌아오면 같은 분·같은 장면·같은 배속으로 멈춘 상태에서 다시 시작하고, ▶ 재개를 누르면 이어진다.
  - 새로 고침이나 창 닫기는 메모리가 사라지므로 예전처럼 다음에 경기 화면을 열 때 남은 시간을 자동 진행한다.
  - 검증: 17분 0:0에서 전술 탭에 다녀왔을 때 라운드가 넘어가지 않았고, 같은 경기 객체·17분·0:0·'재개' 버튼으로 돌아왔다.
- **지난 경기 기록**: 홈에 '지난 경기' 칸을 넣었다(최근 5경기, 펼치면 시즌 전체). 승무패·라운드·홈/원정·상대·스코어·우리 득점자를 보여 주고, 누르면 경기 상세(골 시간·도움, MOM, 점유율·슈팅·xG·패스 성공률·코너·파울·카드)가 나온다. 결과는 원래 저장돼 있었고 보여 주는 화면만 없었다.
- **전술 탭 수치**: 벤치 카드에 능력(OVR)과 포지션 핵심 능력치 3개(1~20, 색으로 높고 낮음)를 넣었다. 경기장 자리에는 '그 자리에서 내는 능력(역할 능력 × 적합도)'을 크게, 적합도를 작게 보여 준다.
- **전술 저장 A·B·C**: 전형(직접 조정한 위치 포함)·선발·팀 지시·세트피스를 통째로 저장하고 불러온다. 불러올 때 떠났거나 뛸 수 없는 선수 자리만 알맞은 선수로 채운다. 다른 전형을 눌러 보다가 공들인 배치를 잃는 문제를 막는다.
- **감독 탭 삭제**: 감독 프로필 페이지·배지·저장 키(`mini-fm-manager`)와 관련 스타일을 지웠다.
- **단장 대화**: '조건도 함께 제안' 체크가 기본으로 켜져 있어, 말만 했는데도 협상 횟수 3번이 금방 바닥났다. 기본을 끄고 설명을 바꿨다. 화면에 없는 조건(임대 후 완전 이적 의무, 분할 지급 등)을 말하면 단장이 같은 대답을 되풀이하지 않고 '그런 조건은 지금 안 된다'고 말하게 했다(워커 규칙 7).

### 47. 개인 매치업과 AI 감독의 경기 중 판단 (구조 추가)
- **배경**: 전술 상성이 팀 단위 규칙(`tactics.js` edges)뿐이라 "어느 선수가 어디서 이기는가"가 결과에 없었고, 상대(AI) 감독은 60·70·80분에 지친 선수를 바꾸는 것 말고는 경기 중에 아무 판단도 하지 않았다.
- **개인 매치업** (`frontend/src/engine/matchups.js` 신설)
  - 통로 4개: 왼쪽 측면(우리 왼쪽 윙 vs 상대 오른쪽 수비), 오른쪽 측면, 중앙(공격수 vs 센터백 + 숫자 싸움), 공중볼(타깃 vs 센터백 높이). 세부 능력치(공격·기술·창의성 / 수비·전술)를 경기 중 실효값(체력·사기 반영)으로 비교한다 → 지친 풀백 쪽이 후반에 뚫린다.
  - 엔진(`match.js` shoot): 오픈 플레이 찬스마다 통로를 고른다. 비중 = 전술이 그 통로를 쓰는 정도(공격 폭·집중 방향·패스 길이) × exp(유불리/12). 고른 통로의 유불리만큼 찬스의 질이 달라지고(±14까지, /220), 측면 통로면 그 측면 선수가 도움을 올리기 쉽다.
  - 유불리(adv)는 **자기 팀 통로 평균 대비**라서 강팀이 통째로 더 세지지 않는다(전체 전력 차는 이미 공격−수비에 들어 있음). "어디로 공격하느냐"만 바뀐다 → 약팀도 한 군데 이기는 매치업을 전술로 파고들 수 있다.
  - 화면: `components/Matchups.jsx` — 경기 전(경기 화면), 경기 중(전술 창, 현재 체력 반영), 전술 화면("다음 상대 매치업")에 선수 이름·1~20 점수·유리/불리와 한 줄 조언. 경기 전 표시는 '그날 컨디션'(경기마다 정해지는 운)을 빼고 본다 — 처음에는 전술 화면(seed 1)과 경기 화면(실제 seed)의 숫자가 2~3점 달라 보였다.
- **AI 감독** (`match.js` aiManage — 예전 aiSubs 대체)
  - 구단마다 성향을 해시로 고정(`aiStyle`): 공격적·균형·실리적. 경기 전 화면에 보여 준다.
  - 46·55·62·70·78·85분에 판단: 점수·시간·성향·전력 차로 운영 단계(−2 잠그기 ~ +2 총공세)를 정해 기본 전술에서 성향·라인·압박·템포를 옮긴다. 실리적 감독은 55분부터 지키고 공격적 감독은 80분까지 안 잠근다. 3골 넘게 지면 체념.
  - 하프타임·70분에 상대 전술 대응: 지시 하나(라인·압박·패스 길이·폭)를 바꿨을 때 상성 점수가 4 이상 좋아지면 바꾼다 (내 전술에도 반응한다).
  - 교체: 경고 받은 수비수·수비형 미드를 미리 빼기(앞서거나 비길 때), 지고 있으면 수비 자원 → 공격수, 앞서면 공격 자원 → 수비형 미드, 지친 선수는 같은 자리로.
  - 퇴장 즉시 대응: 수비수·미드·골키퍼가 나가면 공격 자원을 빼고 그 자리를 메운다(교체 카드가 없으면 중원으로 내린다). 한 명 부족하면 운영을 한 단계 내린다.
  - 판단은 점수·시간·해시만 쓰므로 같은 seed면 같은 결과. 문자 중계에 "🧠 ○○ 벤치: …"로 나온다.
- **검증** (seed 3~4번 평균, 46번 → 47번): 프리미어리그 3골 차 13.3% → 13.6%, 무 24.4% → 22.7%, 홈승 43.8% → 46.3%, 골 2.93 → 2.95 / 분데스리가 3골 차 13.3% → 11.8%, 무 27.0% → 25.7%, 홈승 41.9% → 43.7%. 매치업·AI 전환으로 골이 4%쯤 늘어 `FLOW.base` 0.975 → 0.94로 맞췄다. AI 판단 빈도(프리미어 380경기): 공격 전환 0.93회/경기, 지키기 0.80, 총공세 0.66, 잠그기 0.62, 수비형 투입 0.74, 공격수 투입 0.52, 경고 선수 교체 0.63, 상대 전술 대응 약 0.5, 퇴장 대응 0.05. `check_engine`(불일치 0)·`sim_seasons --check`·빌드 통과. 브라우저에서 전술 화면 → 경기 화면 → 킥오프 → 전술 창 → 종료까지 클릭해 확인.
- **주의**: 압도적인 팀의 주포가 득점을 더 몰아 넣는다(리그 1 Dembélé 34경기 32~37골). 뒤진 상대가 올라오면서 뒷공간을 내주기 때문이다.

### 48. 한 경기 전반에만 내 선수 3명이 다침
- **확률**: 부상은 팀마다 1분에 0.34%라 경기당 평균 약 0.3명입니다. 3,000경기를 돌려 보니 한 팀이 전반에만 3명 이상 다친 경기는 1경기(약 0.03%)였습니다. 운만으로는 거의 안 나오는 일입니다.
- **원인(버그)**: 내 선수가 다치면 경기가 멈추고 교체 화면이 뜹니다. 그런데 교체하지 않고 계속하면 그 선수가 경기장에 남아 있고, 부상 선수를 고를 때 이미 다친 선수를 빼지 않아 **같은 선수가 또 다친 것으로** 처리될 수 있었습니다. 그러면 부상 알림이 여러 번 뜹니다. 교체하지 않고 계속한 3,000경기 중 20경기에서 일어났습니다.
- **해결**: 이미 다친 선수는 부상 후보에서 뺐습니다. 수정 뒤 같은 3,000경기에서 0경기입니다.
- **추가**: 예전에는 태클 강도가 부상과 무관했습니다. 이제 상대가 '거친 태클'이면 우리 팀 부상이 30% 늘고, '부드러운 태클'이면 20% 줄어듭니다.

### 48. AI 구단 운영: 계약 만료·재정·FA 영입·임대 + 판매 희망가 직접 입력
- **배경**: 다른 구단은 경기·성장·이적 사고팔기·시즌 말 선수단 정리만 했다. 계약 기간은 화면에 보였지만 해마다 "지금 시즌 + 1~5년"으로 다시 계산돼 **영영 만료되지 않았고**, 재정은 이적 예산 숫자 하나(`aiCash`)뿐이었다.
- **계약** (`finance.js` aiUntil · `career.js` nextSeason)
  - 다른 구단 선수의 계약은 선수마다 저장하지 않는다. 처음 계약은 선수 ID로 고정(1시즌 기준 1~5년)이라 시즌이 지나면 실제로 줄어든다. 재계약·이적·FA 영입으로 새로 맺은 계약만 `save.aiCt[선수ID] = 만료 시즌`으로 적고, 지난 것은 지운다. 적힌 게 없는데 이미 지난 계약(다른 리그 선수·옛 세이브)은 3년마다 재계약한 것으로 본다.
  - 시즌이 끝날 때 계약이 끝나는 선수는 재계약하거나 FA로 풀린다: 팀 내 11위 안 90% · 18위 안 75% · 그 밖은 23세 이하 70%, 나머지 40% (재정난 구단은 −15%p). 쓸 만한 선수는 FA 시장(`save.released`)에 나오고 메시지함에 요약이 온다. 계약 1년 남은 선수는 몸값이 25% 싸다(`valueOf`의 기존 보정이 이제 실제 계약에 걸린다).
- **재정** (`market.js` runMarket 시즌 초기화): 구단마다 숫자 3개 `aiFin[구단] = [연봉 단가, 매출, 처음 매출]`. 매출은 처음엔 연봉 총액 ÷ 0.62이고 지난 시즌 순위(`save.lastTable`)에 따라 조금씩 변한다(처음의 80~135%). 연봉 총액 = 단가 × 지금 선수단 가중치 합. 이적 예산 = 기본 몫 + 규모의 11% + (매출 × 순위 보정 × 0.62 − 연봉) × 1.2 + 남긴 돈의 절반. 분수에 넘치는 선수단을 꾸리면 예산이 마이너스(**재정난**)가 된다 → 못 사고, 원하는 금액을 10% 깎아서라도 팔고, 해외 매각 대상 1순위가 된다. 내가 그 구단 선수를 살 때도 10% 싸다.
- **FA 영입·임대** (`market.js`): 재정난이 아닌 구단이 약한 자리를 FA로 메운다(라운드당 1건). 여름 시장에는 강한 구단의 벤치 유망주(21세 이하, 팀 내 17위 밖, 성장 여지 4 이상)를 그 선수가 뛸 수 있는 약한 구단으로 한 시즌 임대 보낸다(`save.aiLoans`, 시즌 말 복귀, 성장 계수 0.7 → 1.0). 임대 중인 선수는 살 수 없다.
- **로테이션**: 고칠 것이 없었다. `assignSlots`가 이미 컨디션을 반영한다(0.72 + 0.28 × 컨디션). 14라운드 측정에서 컨디션 80 미만인 능력 상위 11명 676명·경기 중 205명(30%)이 선발에서 빠졌다.
- **화면** (`Transfer.jsx` · `FreeAgents.jsx`): 영입 목록에 ⏳계약 1년 · 💸재정난 · 🔁임대 중 표시와 "⏳ 계약 1년 남음" 필터, FA 목록의 전 소속을 구단 이름으로, 이적 소식에 FA 영입·임대 표시.
- **판매 희망가**: 몸값의 80~200% 중에서 고르는 목록뿐이라 원하는 금액을 넣을 수 없었다 → 금액(€M)을 직접 입력하는 칸 + 80·100·120·150% 빠른 버튼. 입력 칸을 선수 줄 안에 두면 좁은 화면에서 이름 칸이 찌그러져서 줄 아래 별도 줄로 뺐다. 안내 문구에 "제안은 경기를 치를 때마다(라운드가 넘어갈 때), 이적 시장이 열려 있는 동안, 판매 등록한 선수는 매 라운드 1건(능력 78 이상 2건)"을 적었다.
- **세이브**: 새 필드(`aiCt`·`aiFin`·`aiLoans`·`aiTally`·`aiStat`·`lastTable`)는 없으면 기본값으로 동작해서 기존 세이브가 그대로 이어진다(재정은 다음 시즌 시작 때 지금 선수단 기준으로 처음 만들어진다). 6시즌 뒤에도 합쳐서 약 5~6KB.
- **검증**: `tools/sim_seasons.mjs`에 지표(계약 만료·재계약·FA 시장행, FA 풀, FA 영입, 임대, 이적 예산 최소·중앙·최대, 재정난 구단 수, 저장 크기)와 `--check` 범위 8개를 추가. 프리미어리그·분데스리가·에레디비시 6시즌 모두 통과 — 구단당 계약 만료 6.7~6.9명/시즌, 재계약 72%, FA 영입 6~7건/시즌, 임대 5~6건/시즌, 재정난 구단 최대 7/19(프리미어)·4/17(분데스)·1/17(에레디비시), 리그 평균 전력 변화 +0.99 / +0.83 / +2.10(이전 +0.75 / +0.79 / +1.67). `check_engine` 통과. 브라우저에서 판매 등록 → 희망가 17.5 직접 입력 → 저장 확인, 영입 탭의 계약 1년 표시(40명 중 8명), FA 탭의 다른 구단 출신 FA(전 소속 구단명) 확인.
- **안 한 것 / 주의**: 이적 조항(셀온·임대 후 완전 영입 옵션·바이아웃)은 넣지 않았다. 재정난·임대 중 표시는 브라우저에서 시험용 값을 넣어 확인했다(실제 발생은 시뮬레이션으로 확인). 처음 재정난 구단이 생길 때는 경고가 없다 — 3~4시즌째부터 나온다. 에레디비시는 리그 평균 전력 변화가 +2.10으로 한계(2.5)에 가깝다.

### 49. 이적 조항: 바이아웃 · 셀온 · 임대 후 완전 영입 옵션
- **바이아웃** (`trade.js` buyoutOf · `store.jsx` bidFor): 다른 구단 선수 10명 중 3명에게 있다(선수 ID로 고정, 저장 안 함). 금액은 기본 몸값의 110~160%. 현금으로 그 금액을 내면 구단이 거절할 수 없다 — 핵심 선수(보통 몸값의 130%를 부른다)를 더 싸게 데려오거나, 협상 횟수를 다 썼어도 데려올 수 있다. 영입 목록에 🔓바이아웃 표시, 협상 창에 금액과 "이 금액으로 맞추기" 버튼.
- **셀온 15%**
  - 팔 때: 영입 제안 메일에 "📎 셀온 붙여 수락" — 지금은 8% 덜 받고(`SELL_ON_NOW`), 그 선수가 나중에 이적료를 받고 다시 팔리면 15%가 들어온다(`save.sellOn`, `market.js` sellOnHit — 같은 리그 이적·해외 매각·큰 구단의 영입 모두). 판매 탭에 보유한 셀온 목록.
  - 살 때: 협상 창에서 "📎 셀온 15% 주기"를 켜면 상대가 원하는 금액을 7% 깎아 준다. 대신 그 선수를 팔 때(제안 수락·강제 매각) 이적료의 15%를 원래 구단에 준다(`save.sellOnOwed`, 선수 상세에 표시).
- **임대 후 완전 영입 옵션**
  - 빌려 올 때: 옵션을 붙이면 임대료를 20% 더 요구하지만, 시즌 중 언제든 정해 둔 금액(임대 시점 몸값의 115%)에 완전히 데려올 수 있다 — 선수 상세의 "완전 영입 옵션 행사"(`store.jsx` buyLoan, 3년 계약, 이적 자금·임금 예산 확인).
  - 빌려 줄 때: "옵션 포함"으로 보내면 시즌이 끝날 때 그 구단이 선수를 14번째 이상 전력으로 보면 70% 확률로 옵션(몸값의 110%)을 행사해 완전히 데려간다 → 이적료가 들어오고 선수는 돌아오지 않는다.
- **세이브**: `sellOn`·`sellOnOwed`와 임대 기록의 `option`만 늘어난다(건당 수십 바이트). 없으면 조항 없음으로 동작해 기존 세이브가 그대로 이어진다.
- **검증**: 스크립트로 다른 구단 선수 전원에 셀온을 걸고 4라운드를 돌려, 이적료가 오간 이적 11건 중 셀온이 걸린 10건에서 수입 알림과 현금 증가를 확인(나머지 1건은 셀온이 없는 해외 선수). 바이아웃 보유 162/591명(27%). `sim_seasons premier-league BRE 5 --check` 통과, 빌드 통과. 브라우저에서 이적 시장 → 🔓바이아웃 선수(아틀레티코 핵심 골키퍼, 몸값 €16M·조항 €19M) → "이 금액으로 맞추기" → 제안하기 → "구단은 이 제안을 거절할 수 없습니다" 확인, 임대 모드의 완전 영입 옵션 문구 확인.
- **안 한 것 / 주의**: 내 선수에게는 바이아웃 조항이 없다(다른 구단이 조항 금액으로 내 선수를 강제로 데려가지 않는다). 다른 구단끼리의 거래에는 조항이 적용되지 않는다. 임대 옵션 행사·셀온 붙여 수락·옵션 포함 임대 보내기는 화면에서 끝까지 눌러 보지 않았다(버튼·문구와 로직만 확인) — 시험 세이브의 돈과 선수단이 바뀌기 때문.

### 50. 금액 입력칸·피로 부상·전형 표시·벤치 부상 표시
- **금액 입력칸에서 앞의 0이 안 지워짐**("050"): 숫자 입력칸(type=number)이 값 0을 가진 채 시작해서 지우기 어려웠다. → 공용 `MoneyInput`(글자 그대로 입력, 숫자·점만 받고 앞의 0은 지움)으로 바꾸고, 바로 아래에 유로·원화 환산(`= €12.5M · 188억원`)을 보여 준다. 이적 제안의 직접 금액 요구, 판매 희망 가격, 연봉 협상 입력칸에 적용.
- **피로 부상**: 예전에는 부상 확률이 체력과 무관했고(누가 다치는지만 지친 선수 쪽으로 기울었다), 피로 부상 종류도 없었다.
  - 출전 선수 평균 체력이 낮을수록 부상이 잦다(기운이 넘치면 0.75배 ~ 평균 체력 45 이하면 1.5배). 경기 전 컨디션이 낮으면 처음부터 지친 상태로 시작한다.
  - 체력 45 미만 선수가 다치면 근육 경련·근육 피로 누적·햄스트링 과부하처럼 피로 부상이 되고 더 오래 빠진다. 30 미만이면 드물게 피로 골절까지.
  - 측정(2,000경기): 경기 전 컨디션 100 → 경기당 부상 0.29명, 75 → 0.43명, 55 → 0.55명(피로 부상 201건, 피로 골절 8건). 평소 평균(0.32명)은 그대로.
- **'4-1-4-1*'**: 이름 끝 `*`는 '전술 탭에서 자리를 직접 조정한 전형'이라는 내부 표시였다. 화면에는 `4-1-4-1 · 직접 조정`으로 보이게 하고, 스쿼드 제목 줄에 눈에 띄는 배지로 넣었다.
- **전술 탭 벤치 카드 부상 표시**: 부상·징계 글자가 능력 숫자 위에 겹쳐 잘 안 보였다. → 카드 아래 빨간 띠(징계는 주황)로 '🚑 3경기'를 보여 주고, 나머지 내용은 흐리게 했다.

### 51. 리그컵 · 대회 상금 · 승격·강등 · 브라질 리그 이름
- **브라질 리그 이름**: '브라질레이랑' → '브라질 세리 A' (데이터 index·시즌 파일·README·임포트 도구). 이탈리아 '세리에 A'와 헷갈리지 않게 '브라질'을 붙였다.
- **대회 상금 점검**: 예전에는 대회 경기마다 '대회 수당'(구단 매출의 1.2% × 대회 등급, 이기면 1.6배)만 있었고 단계 진출·우승 상금이 없었다. → UEFA 2024-25 배분을 반올림한 대략값으로 바꿨다(€M).
  | 대회 | 참가 | 조별 승/무 | 16강 | 8강 | 4강 | 결승 | 우승 보너스 |
  |---|---|---|---|---|---|---|---|
  | 챔피언스리그 | 18.6 | 2.1 / 0.7 | 11 | 12.5 | 15 | 18.5 | 6.5 |
  | 유로파리그 | 4.3 | 0.45 / 0.15 | 1.75 | 2.5 | 4 | 7 | 6 |
  | 컨퍼런스리그 | 3.2 | 0.4 / 0.13 | 1 | 1.5 | 2.5 | 4 | 3 |
  상금은 장부(FFP 손익 포함)에 항목별로 잡히고, 절반은 이사회가 이적 자금으로 돌려준다. 홈경기 관중 수입은 그대로 따로 들어온다.
- **리그컵**: 내 리그의 1부 팀끼리 단판 토너먼트. 잉글랜드는 프리미어리그 + 챔피언십 44팀으로 'EFL 컵'(32강). 참가팀이 16·32보다 많으면 넘치는 만큼만 예비 라운드를 치른다(44팀 → 24팀 예비 12경기 + 20팀 부전승, 20팀 → 8팀 예비 4경기 + 12팀 부전승, 18팀 → 4팀 예비 2경기). 부전승은 유럽 대항전에 나가는 팀이 먼저 받고 나머지는 추첨. 상금은 작고(단계 진출 €0.05~0.6M, 우승 €1M) 홈경기 관중 수입이 주된 돈이다.
  - 유럽 대항전과 리그컵에 동시에 나갈 수 있게, '다음 경기'는 내가 나가는 모든 대회 중 먼저 잡힌 경기를 고른다.
  - 리그컵이 생기기 전의 세이브도 이번 시즌 리그컵이 바로 생긴다.
- **승격·강등 (프리미어리그 ↔ 챔피언십)**: 1부 18~20위 강등, 2부 1·2위 자동 승격 + 3~6위 플레이오프(4강 3-6·4-5, 결승) 승자 승격.
  - 내가 뛰지 않는 쪽 리그는 시즌 말에 전력 기반 득점 모델(포아송)로 한 시즌을 계산한다. 경기 엔진으로 552경기를 돌리면 7초가 걸려 화면이 멈춰서, 같은 평균(경기당 약 2.7골, 홈 승률 약 44%)을 내는 가벼운 모델(약 10ms)을 쓴다.
  - 리그 구성은 세이브(`divisions`)에 기록하고, 시즌 데이터를 불러올 때 두 리그 파일의 팀을 합쳐 팀 목록·일정을 다시 만든다. 이적 시장·리그컵의 다른 리그 명단도 같은 구성을 쓴다.
  - **강등되면**: 예상 매출이 1부 시절의 50%(낙하산 지원금 포함) → 다음 시즌 42% → 그 뒤 34%로 줄어든다. 계약서의 강등 조항으로 연봉 35% 삭감, 이적 자금 절반, 능력 79 이상 스타(최대 3명) 이적 요청, 민심 −15. 이사회 목표는 2부 기준(자동 승격·플레이오프·중위권·잔류)으로 바뀐다.
  - **승격하면**: 매출이 2.2배(최소 프리미어리그 하위권 수준), 이적 자금 추가, 민심 +15, 목표는 1부 잔류부터.
  - 유럽 대항전 출전권은 '지난 시즌 그 리그 순위'로만 정한다. 승격 팀은 지난 시즌 1부 순위에 없어서 뽑히지 않는다.
- **데이터 버그**: 챔피언십에서 셰필드 유나이티드와 셰필드 웬즈데이가 둘 다 팀 ID `SHE`였다. 순위·대회·승강에서 두 팀이 섞일 수 있어서 웬즈데이를 `SHW`로 바꾸고, 임포트 도구가 같은 리그에서 약자가 겹치면 다른 ID를 주게 했다.
- **고친 경쟁 상태**: 시즌이 바뀌는 순간 리그가 바뀌었는데 화면 데이터는 아직 예전 리그라서, 대회가 예전 리그 기준(챔피언십인데 챔피언스리그)으로 만들어졌다. → 데이터의 리그가 세이브의 리그와 같아질 때까지 기다리고, 대회를 만든 리그(`cupLeague`)가 다르면 다시 만든다.
- **검증**(개발용 세이브, 끝나고 되돌림): 브렌트퍼드를 20위로 만든 뒤 다음 시즌 → 챔피언십 24팀에 들어감, 매출 절반·연봉 삭감·스타 이적 요청·EFL 컵만 남음, 플레이오프 결과 소식. 이어서 챔피언십 1위로 만든 뒤 다음 시즌 → 프리미어리그 복귀, 매출 증가, 목표 '1부 잔류', 대회 재구성. 시즌 1 진행 중에는 EFL 컵 32강을 내 경기로 치르고 유로파리그 참가·무승부 수당이 장부에 들어간 것을 확인했다.

### 52. 진단 도구 여러 seed 평균 · 득점 집중 조사 · 매치업 통로를 경기장에 표시
- **진단 도구** (`tools/diag_engine.mjs [리그] [반복]`): 한 번(306~380경기)만 돌리면 승률·무승부가 ±5%p씩 흔들려 46번의 "분데스리가만 홈 승률이 낮다" 같은 착시가 생겼다. 반복 횟수를 주면 seed를 바꿔 시즌을 여러 번 돌려 평균과 시즌별 표준편차(±)를 보여 준다. 시즌별 득점왕, 오픈 플레이 골의 통로 비율도 나온다. 첫 반복은 예전과 같은 seed라 기록해 둔 숫자와 비교할 수 있다.
- **"5골 이상 경기 11%" 기준이 틀렸다**: 진단 표의 괄호 값 11%를 보고 난타전이 많다고 봤는데(15~18%), 득점이 포아송 분포면 평균 2.9골에서 5골 이상은 16.9%가 정상이다. 엔진은 15.5%로 오히려 조금 적다. 기준값을 "그 평균 골 수의 포아송 기준"으로 바꿨고 엔진은 고치지 않았다.
- **득점 집중**(득점왕이 팀 득점의 35~43%, 리그 1 Dembélé 34경기 30~46골)
  - 원인: 슈터 선택이 아니라 **팀이 넣는 골 수**다. 리그에서 압도적인 팀이 시즌 80~100골을 넣고, 그 팀 주포가 페널티·직접 프리킥까지 찬다.
  - 넣은 것: 그 경기에서 이미 골을 넣은 선수는 집중 마크를 받는다(골 하나마다 박스 안 슈팅 기회 ×0.85, `SHOT_W.mark`).
  - 시험하고 넣지 않은 것: ① 한 선수의 슈팅 비중 상한(27~30%) — Dembélé 39 → 35골로만 줄고 프리미어리그 득점왕이 24 → 22골로 떨어졌다. ② 공격력을 같은 포지션 동료 평균과 비교(`SHOT_W.rel` 0.7) — 리그별 공격수 득점 비율 차(50~65%)가 3~4%p만 줄었다. 그 차이의 주된 원인은 리그 데이터의 포지션 표기(윙어를 FW로 적느냐 MF로 적느냐)라서 엔진으로는 못 맞춘다.
- **매치업 통로 표시**: 찬스가 난 통로와 그 통로를 연 선수를 장면에 기록한다(`tick.ch`·`tick.w`). 경기장 그림(`MatchPitch.jsx`)에서 그 선수가 마무리 직전에 공을 잡고, 측면 통로면 공격이 그 쪽으로 가며, 공격 표시가 "왼쪽 측면 공격 / 오른쪽 측면 공격 / 중앙 돌파 / 공중볼 공격"으로 바뀐다. 골 중계 문구 끝에 `[오른쪽 측면]`처럼 통로가 붙고, 골 기록에도 남는다(`scorers[].lane`).
- **검증**(3시즌 평균): 프리미어리그 골 2.90 ±0.01 · 홈승 43.2% ±2.6 · 무 24.6% ±0.8 · 3골 차 12.5% ±1.0 · 득점 포지션 FW 51.6 / MF 36.5 / DF 11.8 · 득점왕 평균 23.3골 · 오픈 플레이 골 통로 왼쪽 31% / 오른쪽 31% / 중앙 30% / 공중볼 9%. `check_engine`(불일치 0), `sim_seasons --check`, 빌드 통과. 브라우저에서 경기를 8배속으로 돌려 "2' 아스널 오른쪽 측면 공격" 같은 표시를 확인.
- **남은 것**: 득점 집중을 제대로 줄이려면 리그 내 전력 격차(압도적인 팀의 득점 수)나 세트피스 키커 분산을 손봐야 한다.
