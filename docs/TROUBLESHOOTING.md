# Mini FM 문제 해결 기록

실제로 플레이하면서 발견한 치명적인 문제와 원인, 해결 방법, 검증 방법을 정리한 기록입니다.
각 항목은 **증상 → 원인 → 해결 → 검증** 순서로 적었습니다.

## UI · 화면

### 1. 경기 중 교체 화면을 스크롤하면 선수 아이콘이 머리글 위로 떠오름
- **증상**: 경기 중 `교체·위치` 시트를 열고 아래로 스크롤하면, 위로 밀려 올라간 경기장의 선수 아이콘(CB·GK 등)이 고정된 시트 머리글(`교체·위치 / 닫기`) 위에 겹쳐 보였다.
- **원인**: CSS 쌓임 순서(stacking) 문제.
  - 시트 머리글은 `position: sticky; z-index: 1`, 경기장 위 선수 버튼(`.slot`)도 `position: absolute; z-index: 1`.
  - 둘의 z-index가 같으면 DOM에서 **뒤에 나오는 요소가 위에** 그려진다. 경기장은 머리글보다 뒤에 있으므로 선수 아이콘이 머리글을 덮었다.
  - 경기장 컨테이너의 `overflow: hidden`은 잘라내기만 할 뿐 **새 쌓임 맥락(stacking context)을 만들지 않아서**, 안쪽 z-index가 바깥 요소와 직접 경쟁했다.
- **해결**:
  - 경기장 컨테이너에 `isolation: isolate`를 줘서 선수 아이콘의 z-index가 경기장 안에서만 비교되게 했다.
  - 시트 머리글의 z-index를 5로 올렸다.
- **검증**: 시트를 260px 스크롤한 상태에서 머리글과 겹치는 선수 4명의 중심 좌표로 `document.elementFromPoint`를 호출했다. 4곳 모두 머리글 요소가 반환됐다.
- **배운 점**: z-index는 같은 쌓임 맥락 안에서만 비교된다. 재사용되는 컴포넌트(경기장)는 `isolation: isolate`로 내부 z-index를 가둬 두는 것이 안전하다.

### 2. PC에서 리그 화면을 내리면 탭 줄만 따라오고 위쪽 내용이 비쳐 보임
- **증상**: PC 화면의 리그·대회 페이지를 스크롤하면 `팀 순위 / 개인 순위 / 일정 / 대항전` 탭 줄이 화면 중간에 붙어 따라오고, 그 위로 대회 헤더 일부가 비쳐 보였다.
- **원인**: 탭 줄이 모바일 기준 `position: sticky; top: calc(58px + safe-area)`로 되어 있었다. 58px은 모바일 상단바 높이다. PC 레이아웃에는 그 상단바가 스크롤 영역 안에 없어서, 탭이 위에서 58px 떨어진 곳에 멈췄고 그 틈으로 뒤 내용이 보였다.
- **해결**: PC 모드(`html.desktop`)에서는 탭 줄을 고정하지 않도록(`position: static`) 바꿨다. 모바일은 기존처럼 상단바 아래에 고정된다.
- **배운 점**: 반응형에서 sticky 오프셋을 고정값으로 두면 레이아웃마다 기준이 달라진다. 레이아웃별로 sticky를 따로 정의해야 한다.

### 3. 탭을 누르면 앱 전체가 멈춤 (SPA 이동 오류)
- **증상**: 하단 탭으로 화면을 옮기면 가끔 빈 화면이 되며 React 오류가 났다. 주소를 직접 입력해서 열 때는 재현되지 않았다.
- **원인**: `useEffect(() => window.scrollTo(0, 0), [pathname])`처럼 중괄호 없이 썼다. 최신 브라우저는 `scrollTo`가 값을 돌려주는데, 그 값이 effect의 정리 함수(cleanup)로 취급돼 다음 이동 때 React가 함수가 아닌 것을 호출하려다 터졌다.
- **해결**: `useEffect(() => { window.scrollTo(0, 0) }, [pathname])`로 중괄호를 넣어 아무것도 반환하지 않게 했다.
- **검증 방식 변경**: URL로 페이지를 여는 테스트만으로는 놓친다. 이후 모든 검증은 **실제 화면 안에서 탭을 클릭하는 E2E 방식**으로 바꿨다.

### 4. 면담 기록이 메시지함에 긴 텍스트 덩어리로 남음
- **증상**: 면담이 끝나면 대화 전문이 한 문단으로 메시지함에 붙어 읽기 어려웠다.
- **원인**: 대화를 `감독: … / 선수: …` 문자열 하나로 합쳐 메일 본문에 저장했다.
- **해결**:
  - 대화를 **구조 데이터**(`{ role, text, mood, delta }` 배열 + 결과·신뢰 변화·약속)로 저장하도록 바꿨다.
  - 메시지함에는 요약 한 줄과 `💬 대화 보기` 버튼만 보이고, 누르면 면담실과 같은 말풍선 화면이 읽기 전용으로 열린다.
  - 예전 텍스트 기록도 줄 단위로 파싱해 말풍선으로 보여준다(하위 호환).

## 게임 로직

### 5. FA 시장에서 같은 선수를 두 번 영입할 수 있음
- **증상**: 영입한 선수가 스쿼드에 두 번 나타났다.
- **원인**:
  - 영입 시 "이미 구단에 있는 선수인지"를 확인하지 않았다.
  - React 상태 갱신이 비동기라서 버튼을 빠르게 두 번 누르면 두 번 모두 통과했다.
- **해결**: 세 겹으로 막았다.
  1. 제안 전에 이미 어느 구단에든 있는 선수면 거절한다.
  2. 상태 갱신 함수 안에서 최신 로스터를 기준으로 다시 확인한다(연속 클릭 대비).
  3. 화면에 그릴 때도 ID를 중복 제거한다.

  이미 꼬인 저장 데이터는 앱을 열 때 자동으로 정리한다(로스터 중복 제거).
- **검증**: 제안 버튼을 일부러 더블 클릭해도 로스터가 1명만 늘었다.

### 6. 부상으로 10명이 되면 빈 자리를 다시 채울 수 없음
- **증상**: 경기 중 부상자가 나와 10명으로 계속하면, 그 자리(예: CB)에 교체 선수를 넣을 방법이 없었다.
- **원인**: 출전 선수 목록에서 부상자를 지우면서 자리 정보까지 함께 사라졌다.
- **해결**: 경기 상태에 **빈 자리(vacant)** 를 따로 기록해 역할(CB 등)을 보존했다. 교체 화면에서 빈 자리에 선수를 넣거나 다른 포지션 선수를 옮길 수 있게 했다.

### 7. 대항전에서 다른 리그의 같은 약칭 팀이 섞임
- **증상**: 바르셀로나와 바이에른이 같은 `FCB`로 겹쳐 결과가 꼬였다.
- **원인**: 팀 ID가 리그 안에서만 고유했다.
- **해결**: 대회 안에서는 `리그ID/팀ID` 복합 키를 쓰도록 바꿨다.

### 8. 팀 OVR이 포지션에 안 맞는 선수를 세워도 그대로임
- **증상**: 공격수를 수비 자리에 세워도 팀 OVR이 그대로라서 문제를 알아차릴 수 없었다.
- **원인**: 팀 OVR을 "가장 높은 11명 평균"으로 계산해 실제 라인업과 무관했다. (경기 엔진에는 이미 자리 적합도가 반영돼 있었다. 400경기 시뮬레이션에서 공격수·수비수 3명을 맞바꾸면 승리 117 → 46.)
- **해결**: **라인업 OVR = 자리마다 (선수 OVR × 자리 적합도)의 평균**으로 바꾸고 홈·스쿼드·전술·경기 준비 화면에 표시했다. 맞지 않는 자리에 선 선수는 `ST→LB 50%`처럼 경고한다.

## 경기 엔진 · 밸런스

### 9. 사기·전술이 결과에 거의 영향이 없고, 전력 차가 결과를 거의 결정함
- **측정**: 같은 조건으로 400~500경기씩 시뮬레이션했다.

  | 항목 | 수정 전 | 수정 후 |
  |---|---|---|
  | 동급 팀 홈 승률 | 54% | 43~47% |
  | OVR +10 팀 승률 | 86% | 72% |
  | 사기 15 vs 95 | 차이 없음 | 약 ±8% 능력치 차이 |
  | 약팀이 버스 세우기로 강팀(게겐프레싱) 상대 | 승 23% · 패 55% | 승 34% · 패 37% |

- **원인**:
  - 사기 효과가 ±3%로 너무 작았다.
  - 전술 효과(운영·압박·라인)가 선수 능력치에 더해져서, 능력치 차이를 완화하려고 만든 큰 나눗셈 계수에 같이 묻혔다.
- **해결**:
  - 사기 ±8%, 폼 ±5%로 키웠다.
  - 경기마다 "그날 컨디션"(±4%)을 넣어 이변이 나오게 했다.
  - **전술 상성을 선수 능력과 분리해 약 3배 큰 가중치**로 반영했다(역습 vs 높은 라인, 측면 공격 vs 측면 수비 부족, 압박 vs 짧은 빌드업 등).
  - 경기 전에 같은 조건으로 70~120경기를 미리 돌려 **예상 승률**을 보여준다.

### 10. 경기장 선수들이 대형 그대로 딱딱하게 움직임
- **원인**: 1분에 한 장면만 계산해서 대형 전체가 통째로 밀렸다.
- **해결**: 1분을 패스 2~3번으로 나누고 역할별로 움직이게 했다.
  - 공격 진행도에 따라 라인이 올라간다.
  - 풀백은 공 쪽 측면으로 오버래핑하고, 윙어는 안쪽으로 파고들고, 스트라이커는 뒷공간으로 침투한다.
  - 수비는 공 쪽으로 좁혀 서고, 압박과 커버를 나눠 맡는다.
  - 선수마다 고유한 위상의 흔들림을 줬다.

## 외부 API · 배포

### 11. AI 면담 응답이 최대 20초 걸림
- **측정**: 같은 요청을 반복하니 3.8초, 19.9초로 들쭉날쭉했다.
- **원인**: 기본 모델이 답하기 전에 "생각" 단계를 거쳤다. 생각을 끄는 옵션(`thinkingBudget: 0`)은 최신 모델에서 400 오류를 냈다.
- **해결**:
  - 경량 모델을 먼저 호출하고, 실패(429·503·400)하거나 12초를 넘기면 다음 모델로 넘어간다.
  - 게임은 20초 안에 응답이 없으면 규칙 기반 대화로 자동 전환해 화면이 멈추지 않게 했다.
- **결과**: 평균 **약 1.3초**.

### 12. AI 키를 안전하게 쓰기 (정적 호스팅 + 비밀값)
- **문제**: GitHub Pages는 정적 호스팅이라 브라우저 코드에 API 키를 넣으면 누구나 볼 수 있다.
- **해결**:
  - Cloudflare Worker를 **중계 서버**로 두고 Gemini 키는 Worker 비밀값(`wrangler secret put`)에만 저장했다.
  - CORS는 게임 주소만 허용한다.
  - 사용자가 키를 터미널에 직접 붙여 넣어서, 대화 기록·저장소·작업 로그 어디에도 키가 남지 않는다.
  - SportsAPI·football-data 키도 GitHub Actions Secrets에만 둔다.

### 13. 선수 능력치를 실제 데이터로 바꾸기 (하루 100회 제한)
- **문제**: 기존 능력치가 "지난 시즌 순위 + 무작위 값"이라 주전과 후보, 리그 간 수준 차이가 없었다.
- **해결**:
  - SportsAPI Pro의 팀 명단(시장가치·세부 포지션)으로 OVR을 계산하고, 선수별 능력치 레이더로 공격·수비 비중을 보정했다.
  - 무료 한도(하루 100회) 때문에 **GitHub Actions가 매일 이어서 수집**하고, 진행 상태(ID 대응표)를 커밋해서 다음 날 이어간다.
  - 약관상 원본 응답은 공개하지 않고 **계산한 결과만** 저장소에 올린다.
- **겪은 문제**:
  - 순위표 응답 형식이 문서와 달라(평평한 배열) 첫 실행에서 팀 목록이 비었다. 4회만 쓰는 시험 실행으로 먼저 확인하고 고쳤다.
  - 이적·강등 선수가 매칭되지 않아 **전체 리그 기준 매칭**과 한 단어 이름 규칙을 추가했다.

### 14. GitHub Actions가 커밋해도 사이트가 다시 배포되지 않음
- **원인**: `GITHUB_TOKEN`으로 push한 커밋은 다른 워크플로를 트리거하지 않는다.
- **해결**: 데이터 수집 워크플로 끝에서 `gh workflow run pages.yml`로 배포를 직접 실행한다. 동시에 커밋이 올라와 push가 거절되는 경우를 위해 `git pull --rebase` 후 push한다.

### 15. 앱 내장 브라우저에서 Google AI Studio 키 발급 실패
- **증상**: 로그인은 됐지만 키 목록과 키 만들기에서 `permission denied`가 났다.
- **원인**: 내장 브라우저가 Google 도메인 사이의 인증 쿠키를 막아 API 호출이 실패했다.
- **해결**: 실제 Chrome에서 브라우저 자동화(Claude in Chrome)로 발급했다. 전용 프로젝트 `mini-fm`과 키 이름 `mini-fm 게임 AI 대화`로 구분했다.

### 16. PowerShell에서 `npx`가 실행되지 않음
- **원인**: Windows 실행 정책이 `npx.ps1` 스크립트를 막았다.
- **해결**: 보안 설정을 바꾸지 않고 `npx.cmd`를 직접 호출했다.

## 게임 밸런스 (플레이 피드백)

### 17. 내 선수를 팔면 헐값에 팔림
- **증상**: 판매 목록에 올린 선수에게 몸값의 절반 수준 제안이 오고, 수락·거절밖에 할 수 없었다.
- **원인**:
  - 상대 제안이 몸값의 80~120% 중 무작위였다.
  - 계약 1년 남음(−35%)과 이적 요청(−20%) 할인이 곱해져 기준 몸값 자체가 크게 낮아졌다.
  - 역제안 수단이 없었다.
- **해결**:
  - **희망 가격**(몸값의 80~200%)을 정해 판매 목록에 올린다.
  - 상대 구단마다 **최대 금액**(선수 수준에 따라 몸값의 115~135%)이 있다. 첫 제안은 희망가보다 조금 낮게 온다.
  - **"더 달라고 하기"**: 상대 최대 금액 안이면 합의하고, 넘으면 중간 금액으로 한 번 '최종 제안'을 받으며, 그다음에는 결렬된다.
  - OVR 78 이상 선수는 두 구단이 경쟁한다.
  - 할인을 완화했다(계약 1년 −25%, 이적 요청 −15%). 강제 매각은 75~100%로 고정했다.
- **검증**: 분데스리가 선수 3명으로 시뮬레이션한 결과, 첫 제안이 몸값의 87~115%였고 역제안으로 희망가까지 올릴 수 있었다.

### 18. 꾸준히 출전시켰는데도 평점이 나쁘면 이적 요청
- **원인**: 경기 평점이 사기에 크게 반영되고(평점 1점당 사기 ±4), 사기가 25 아래로 떨어지면 **이유와 상관없이** 이적을 요청했다.
- **해결**:
  - 출전 선수의 평점 영향을 줄였다(최대 −3).
  - 이적 요청은 **사기가 바닥이면서 분명한 이유가 있을 때만** 나온다. 이유는 5경기 이상 벤치, 감독 신뢰 25 미만, 연봉이 적정의 60% 미만인 경우다. 진행 중인 약속이 있으면 요청하지 않는다.
  - **연봉 인상 요구 면담**을 추가했다. 활약(최근 평점 7.1 이상)이나 주전급인데 연봉이 적정의 75% 미만이면 시즌에 한 번 면담을 요청하고, 약속하면 5라운드 안에 재계약해야 지킨 것으로 판정된다.
